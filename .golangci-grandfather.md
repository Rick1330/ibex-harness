# golangci-lint grandfather policy (Wave 1 / MF-002)

Architecture import boundaries are enforced **without** grandfathering:

- `depguard` rule `packages-no-services` blocks `packages/**` from importing `github.com/Rick1330/ibex-harness/services/**`.

Complexity linters use a **new-issues-only** policy on PRs:

- `funlen` (≤40 lines, ≤30 statements) and `gocognit` (≤10) are enabled.
- `issues.new: true` with `new-from-merge-base: main` suppresses existing production hotspots.
- `_test.go` files are excluded from both linters (table-driven tests).

## Removing grandfather entries

As Waves 2–4 shrink hotspots (MF-003, MF-016), new code in those areas must meet limits immediately. Refactors that touch grandfathered functions should shrink them below thresholds when practical.

## Proxy `database/sql` (MF-001)

`services/proxy/cmd/proxy/main.go` still opens Postgres for session/directive stores. A separate `depguard` deny on `database/sql` in proxy is **deferred** until MF-001 ADR/product decision.
