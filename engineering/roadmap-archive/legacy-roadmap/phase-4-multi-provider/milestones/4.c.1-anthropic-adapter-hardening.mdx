<Callout type="note" title="Planning baseline (sketch deviations)">
  Shipped shape differs from the early “harden a Phase 2.5 prototype” sketch:

  1. **`Registry.For("claude-*")` was never real** — resolution uses exact model IDs (e.g. `Registry.For("claude-sonnet-4-5")`). `NewRegistry` returns `ErrDuplicateModel` on ID collision across providers (not a panic on “duplicate prefixes”).
  2. **SSE translation, not dual-write** — Anthropic translates Anthropic named SSE → OpenAI-shaped `chat.completion.chunk` + `[DONE]`. ADR-0027 dual-write in the proxy is unaffected because it only ever sees OpenAI-shaped SSE (OpenAI adapter remains verbatim passthrough).
  3. **Tools / images / thinking passthrough are out of scope** — text-only per ADR-0040. The capability catalog may still advertise `SupportsTools` / `SupportsVision` as vendor truth; that catalog/adapter tension is accepted here, not a bug to fix in this milestone.
  4. **`ANTHROPIC_API_VERSION` env override was considered and declined** — version stays pinned at `2023-06-01` in `packages/provider/anthropic/config.go` (`defaultAPIVersion`), set on every Messages request via `newMessagesRequest`.
</Callout>

## Why This Milestone Exists

The Anthropic adapter already shipped in Phase 2.5 (**2.5.G1.M1**) and is documented in [ADR-0040](/docs/adr/0040-anthropic-provider-adapter) (Accepted 2026-08-21): OpenAI-compatible SSE translation, `anthropic-version` on every request, system-role extraction (leading + mid-conversation fold), and mid-stream `event: error` → pipe `CloseWithError` (no JSON-swap). Phase 2.5’s exit gate already checked Anthropic test-depth parity with OpenAI.

This milestone is therefore **not** a greenfield hardening pass. It closes roadmap drift against live code and adds two small, additive stream-translate test assertions (incomplete mid-stream body; explicit ignore of non-text delta types). No adapter behavior change; no proxy handler/middleware changes.

## Shipped surface (already in tree)

### Request construction

- `packages/provider/anthropic/request.go` — peel leading `system` messages + fold mid-conversation systems into top-level `system`; reject `tool` role; deny-by-default passthrough allowlist (text-only).
- `packages/provider/anthropic/client.go` — `newMessagesRequest` sets `x-api-key`, `anthropic-version`, `Content-Type` on every Messages call.

### Streaming translation

- `packages/provider/anthropic/stream_translate.go` — Anthropic named events → OpenAI-compatible SSE; non-`text_delta` content deltas ignored; mid-stream `event: error` → `CloseWithError` (no `[DONE]`, no fabricated OpenAI error chunk in the pipe body).
- Retry does not re-issue after a live stream body has started (`retry.go`).

### Registry / capabilities

- Built-in IDs: `claude-sonnet-4-5`, `claude-haiku-4-5`, `claude-opus-4-5` (+ `ExtraModels`).
- Capability rows in `capability_catalog.go` (context window / streaming flags); tools/vision flags are vendor-capability metadata, not a claim that the adapter implements tool/image passthrough.

## Success signals

- [x] Exact-ID `Registry.For("claude-sonnet-4-5")` (and sibling Claude IDs) resolves when Anthropic is registered; `NewRegistry` returns `ErrDuplicateModel` on colliding model IDs
- [x] Streaming translation emits OpenAI-shaped chunks suitable for ADR-0027 dual-write; mid-stream Anthropic `event: error` terminates the translate pipe as incomplete (no `data: [DONE]`, no fabricated OpenAI-shaped error chunk) — asserted in `stream_translate_test.go`
- [x] Anthropic HTTP / mapped provider errors continue through `provider.MapError` / existing failure paths — no proxy handler special-case for Anthropic
- [x] Non-streaming and streaming fixture coverage lives in `packages/provider/anthropic` (inline httptest / SSE fixtures; no separate golden-file harness required)
- [x] Zero proxy handler or middleware changes for this milestone (docs + Anthropic package tests only)
- [x] Non-text stream deltas (`input_json_delta`, `thinking_delta`, `signature_delta`) are ignored without leaking into OpenAI-shaped output
