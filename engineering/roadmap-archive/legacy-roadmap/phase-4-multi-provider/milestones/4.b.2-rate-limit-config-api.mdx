<Callout type="note" title="Planning baseline (sketch deviations)">
  Shipped shape differs from the early sketch in these locked ways:

  1. **RPM only** — no `tokens_per_month` column or month-token enforcement (follow-up [#806](https://github.com/Rick1330/ibex-harness/issues/806)).
  2. **No usage time-series** endpoint (`GET /v1/agents/.../rate-limits/usage` deferred).
  3. Channel is `ratelimit_config_updates:{org_id}` (directive-style), not `ratelimit:config:updated:…`.
  4. Proxy reload uses **pub/sub + 30s full poll** (poll is the miss/fallback path).
  5. New table `ibex_core.rate_limit_overrides` only — no `ibex_billing.*` tables.
  6. Uniqueness: `UNIQUE (org_id, agent_id)` plus **partial unique index** on `(org_id) WHERE agent_id IS NULL`.
  7. Authz: GET = bearer + path-org match; PATCH = owner/admin + OrgSettingsWrite (bit 35); live role `viewer` (not sketch `read_only`).
  8. Cross-tenant → **404** (`TestAPI_ISO_RATELIMIT_*`).
  9. Redis fail-open on hot path preserved; config reload failures keep last-good / env defaults.
</Callout>

## Why This Milestone Exists

The Lua limiter (4.B.1) needs per-org and per-agent limits sourced from configuration, not hard-coded constants. Operators should be able to adjust these limits without a service restart. Configuration is stored in Postgres, read into the proxy's in-memory config on a 30s poll or Redis pub/sub invalidation — never a per-request DB read on the hot path.

---

## Non-Goals

- Rate-limit metering/billing integration (Phase 4.5)
- Per-user rate limits
- Global platform limit configuration (that's an operator-level infrastructure setting, not an API endpoint)
- Token-spend / month_tokens ceilings ([#806](https://github.com/Rick1330/ibex-harness/issues/806))

## Shipped surface

```
GET  /v1/organizations/{org_id}/rate-limits
PATCH /v1/organizations/{org_id}/rate-limits
```

- Migration `000028_rate_limit_overrides`
- `packages/ratelimit` config plane (`config_*` + mutable `HierarchicalLimiter` overrides)
- Proxy bootstrap watcher (pub/sub + 30s poll)
- Management API publish on `ratelimit_config_updates:{org_id}` after commit (publish fail does not roll back PG)

## Success signals

- [x] `PATCH` reflected via pub/sub within ~1s or via ≤30s poll — unit tests record latencies
- [x] `GET` `current_minute_requests` uses Redis org RPM key (or `0` if Redis optional/unavailable)
- [x] owner/admin `PATCH` OK; member/viewer `PATCH` → 403
- [x] `TestAPI_ISO_RATELIMIT_*`: foreign org GET/PATCH → 404
