## Why This Milestone Exists

Milestone 3.D.1 returns search hits in raw retrieval order (cosine similarity for vector, `ts_rank_cd` for GIN supplemental rows). Category-conditional composite scoring and the per-category half-life table already ship in Track B (`app/scoring/`, write hot-cache ZADD). **3.D.2 wires that scorer into the read path** so `find_similar` and `POST /v1/memories/search` order results by `composite_score()` after merge/hydrate. HTTP `similarity` remains the retrieval metric; `rank` reflects post-composite order.

FTS supplemental hits use a fixed relevance sentinel (`0.5`) for composite scoring only — they have no cosine score. See [ADR-0058](/docs/adr/0058-semantic-search-fts-fallback-trigger).

### Per-category half-life table (reference — implemented in 3.2.1)

```python
CATEGORY_HALF_LIFE_DAYS: Final[dict[str, float]] = {
 "factual": 180.0, # facts decay slowly
 "procedural": 120.0, # how-to knowledge is durable
 "preference": 45.0, # preferences drift moderately
 "behavioral": 30.0, # patterns can shift faster
 "episodic": 14.0, # events are most time-sensitive (original constant, now scoped correctly)
}
```

The half-life table lives in `app/scoring/half_life.py` today. Optional follow-up: expose
values via environment variables for ops tuning without redeploy — **not** a 3.D.2 blocker.
