# ADR-0075 — Per-Org Model Routing Policy

## Status

Accepted (Milestone 4.C.2)

## Context

`Registry.For(model)` is an exact platform map with no org awareness. Exit criteria require per-org allow/deny over requested models. Credentials use Auth gRPC because they are secrets (ADR-0074); org model policy is non-secret config closer to directives and rate-limit overrides. Auth's `ValidateAgent` does not return `default_model` (4.A.3 columns exist only in Postgres).

## Decision

1. **`OrgAwareRegistry` wraps** `*provider.Registry`; do not change `For(model)` signature or exact-match semantics.
2. **Precedence:** trimmed request-body `model` if non-empty; else proxy Postgres `agents.default_model` for the verified agent; else 400 `model is required`. Org policy is then a **veto** (priority ASC, first `filepath.Match` wins). No match → allow any registered model. Then `Registry.For`. `default_provider` is not used for registry lookup.
3. **Deny** → `403 MODEL_NOT_ALLOWED`. Unknown model after allow → existing `501 PROVIDER_NOT_CONFIGURED`.
4. **Direct Postgres** from the proxy (`packages/modelpolicy` store + RLS). No Auth gRPC hop.
5. **Cache:** dedicated bloom→LRU in `packages/modelpolicy` (not `packages/authcache`), **60s TTL**, Redis pub/sub `model_policy_updates:{org_id}` via `packages/redissub.Loop`. Policy load errors **fail closed** (503).
6. **No `fallback_chain` column** in 4.C.2 — deferred to 4.C.4 when a reader exists.
7. **Admin CRUD** under `/v1/organizations/{org_id}/model-policies` with `RequireOrgSettings` on writes; soft glob-syntax validation only (not #790 registry allowlist).
8. **Middleware change is required:** `ProviderRoutingMiddleware` reads `auth.FromContext` org ID and calls `ForOrg` — handlers remain registry-agnostic.

## Consequences

- Chat parse allows empty `model` so agent-default fill can run before the policy gate.
- Management API publishes invalidation events; proxy subscribers drop LRU entries for that org.
- Glob dialect is Go `filepath.Match` (`*` / `?` only).
