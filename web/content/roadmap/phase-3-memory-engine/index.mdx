## What Phase 3 Delivers

Phase 3 proves memory can be **written, deduplicated, conflict-checked, and retrieved correctly and
fast** — in isolation, testable via direct API calls. It deliberately does **not** touch the proxy hot
path or auto-extraction; that is Phase 3.5. This mirrors how Phase 1 (auth/proxy plumbing) was kept
separate from Phase 2 (actual LLM forwarding).

## Why the Original Plan Needed This Rewrite

1. **IVFFlat replaced by HNSW:** The original plan specified IVFFlat (lists=100) with HNSW deferred to Phase 4. Since Phase 3 is greenfield (no existing index to migrate), starting with the better index avoids a costly live-traffic migration later.
2. **Multi-label categories:** The original single `category` enum cannot represent memories that span multiple categories. A join table (`memory_labels`) replaces the exclusive enum.
3. **Temporal validity:** The original schema had no notion of when a fact was true, causing false contradictions when facts change over time. `valid_from`/`valid_until` columns fix this.

## Phase 3 Exit Criteria

Verified in [phase3-exit-audit](/roadmap/phase-3-memory-engine/phase3-exit-audit) (`45696a2`):

1. Memory write pipeline (9 steps) passes all unit + ISO-\* integration tests
2. HNSW recall@10 ≥ 98% on committed CI profile (`has_1m` optional on smoke/fast per ADR-0061)
3. Temporal-interval-aware conflict detection: sequential-fact auto-supersedes; overlapping intervals escalate; zero LLM on non-overlapping intervals
4. Retrieval-quality benchmarks in CI with committed baselines (HNSW, ranking-quality, write-pipeline)
5. All 12 ISO-\* cross-tenant isolation cases pass, including `memory_relationships` cross-org edge case
6. Per-memory FK cascade verified (ISO-2.1); org-scope GDPR + MinIO deferred to [Phase 4.A.2](https://github.com/Rick1330/ibex-harness/issues/641)
7. Phase 1 and Phase 2 security regression tests pass (`security-integration`)
8. `make e2e-smoke-p3-memory` exits 0
9. Phase 3 memory ADRs published (0047–0049, 0052–0061) and cross-linked from the [decision log](/roadmap/phase-3-memory-engine/decisions)
10. **No proxy hot-path changes** — handler/middleware unchanged during Phase 3 (Phase 3.5 boundary)

**Relocated to Phase 3.5.E.2:** MCP `search_memory`/`write_memory` E2E with ClickHouse tracing (stubs only in Phase 3 per ADR-0050).
