## Track B — Vector Store & Embedding Integration

### Goal 3.B: Pluggable vector store with category-conditional composite scoring

**Milestones:**
- **3.2.1 — VectorStore interface + pgvector-HNSW implementation:** `VectorStore` ABC, `PgVectorStore` with `SET LOCAL hnsw.ef_search` per-transaction. Composite scoring v2 with category-conditional half-life (factual: 180d, procedural: 120d, preference: 45d, behavioral: 30d, episodic: 14d). Embedding client calling Phase 2.5's embedder service. Recall/latency benchmark at 10K/100K/1M synthetic rows.

**Acceptance criteria:**
- `VectorStore` ABC with `PgVectorStore` implementation, `ef_search` set per-transaction
- Composite scoring v2 unit-tested against documented formula
- Benchmark run at 10K/100K/1M rows, results committed
- `embedding_client.py` has zero direct ML library imports

## Track C — Memory Write Pipeline

### Goal 3.C: 9-step write pipeline with PII detection, dedup, and temporal conflict resolution

**Milestones:**
- **3.C.1 — PII detection and redaction:** Two-tier detection via Microsoft Presidio (regex patterns + NER). Redaction before embedding. Quarantine for low-confidence PII findings.
- **3.C.2 — Content and near-duplicate detection:** SHA-256 content hash for exact dedup. Cosine > 0.92 for near-duplicate candidate detection.
- **3.C.3 — Temporal-interval-aware conflict detection:** Interval overlap check before LLM escalation. Sequential facts (`valid_from` ordering) auto-classified as `supersedes` with zero LLM calls. [ADR-0056](/docs/adr/0056-temporal-conflict-detection) (temporal-first design).
- **3.C.5 — Write-path persistence & orchestration:** DB insert, apply `pending_supersede_targets`, unique-violation→bump, after-commit cache/index, durable `memory_conflict_escalations`. [ADR-0057](/docs/adr/0057-memory-write-orchestration). **Shipped.**
- **3.C.4 — Multi-label memory classification:** `memory_labels` join table populated at insert; optional `labels[]` on `POST /v1/memories`. [ADR-0048](/docs/adr/0048-memory-multi-label-categories). **Shipped** (extraction-worker prompt is Phase 3.5).

**Acceptance criteria:**
- Sequential-fact fixture classified as `supersedes` with zero LLM calls
- Genuinely overlapping-interval contradiction still escalates to LLM correctly
- PII detection: &gt;95% recall on structured PII, NER-based detection for names/addresses
- Redaction happens strictly before embedding (pipeline ordering test)

## Track D — Read/Ranking Pipeline & Hot Cache

### Goal 3.D: Semantic search, composite scoring, and hot cache

**Milestones:**
- **3.D.1 — Semantic search read path:** `find_similar` via `VectorStore.search()`, GIN full-text fallback when vector results < K.
- **3.D.2 — Composite scoring in search ranking:** Wire existing `composite_score()` (category-conditional half-life from 3.2.1) into `find_similar` after retrieval. HTTP `similarity` stays the retrieval metric; ordering uses composite. HTTP regression proves old factual outranks fresh episodic at equal vector relevance.
- **3.D.3 — Hot cache (Redis sorted set):** **Shipped** — `MemoryHotCacheReader`, atomic top-50 trim, hydrate-time filtering ([ADR-0059](/docs/adr/0059-hot-cache-read-path)).

**Acceptance criteria:**
- `find_similar` uses HNSW index (confirmed via `EXPLAIN ANALYZE`)
- Cross-org result leakage impossible (integration test)
- Hot cache score formula reuses `CATEGORY_HALF_LIFE_DAYS`
