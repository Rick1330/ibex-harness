## Delivered

- `MemoryReadRepository.find_similar()` — vector primary, GIN supplemental when sparse
- `POST /v1/memories/search` — `memory:read`, minimal request (`agent_id`, `query`, `limit`, `min_similarity`, `min_confidence`)
- Fallback trigger: `len(hydrated_vector_results) < limit` — caller-relative, not a fixed constant ([ADR-0058](/docs/adr/0058-semantic-search-fts-fallback-trigger))
- Merge: vector hits first (desc similarity), FTS append (desc `ts_rank_cd`), dedupe by id, cap at `limit`
- Metric: `ibex_memory_search_fallback_total{triggered}` (increments only when FTS returns new candidates)
- Toggle: `IBEX_MEMORY_SEARCH_FALLBACK_ENABLED` (default true)

### Fallback trigger semantics

"Sparse" means the caller's page is unfilled after vector search + hydrate — whether because corpus &lt; `limit`, `min_similarity` filtered ANN hits, or `min_confidence` dropped rows. There is **no** fixed `VECTOR_FALLBACK_THRESHOLD`; Phase 3 goals "vector results &lt; K" means caller `limit` (K), not a magic number.

| Scenario | limit | Condition | FTS fires? |
| --- | --- | --- | --- |
| Typical agent | 10 (default) | 15 memories, all pass filters | No |
| Small agent | 10 | 8 memories | Yes |
| Large limit | 20 | 15 memories | Yes |
| Full page | 3 | ≥3 vector hits after hydrate | No |
