# Milestone 3.4.2 — Session Incremental Read Pointer

**Status:** Planned  
**Goal:** [3.4 — Memory extraction worker](/roadmap/phase-3-memory-engine/goals#goal-34-memory-extraction-worker)  
**Phase:** 3 — Memory Engine and Operator Platform  
**Estimated effort:** 2 days  
**Hard dependency:** [2.4.4 Session idle-timeout sweeper](/roadmap/phase-2-single-provider/milestones/2.4.4-session-idle-timeout-sweeper)

---

## Why This Milestone Exists

The extraction worker must advance a per-session read pointer (`last_extracted_turn`) so each turn is processed exactly once. Sessions that stay `active` forever never become eligible — without an idle sweeper, memory extraction is effectively dead in production even if every Phase 3 milestone ships.

---

## Hard dependency on 2.4.4

Clients rarely send `X-IBEX-Session-End`. [Milestone 2.4.4](/roadmap/phase-2-single-provider/milestones/2.4.4-session-idle-timeout-sweeper) marks idle sessions `abandoned`. This milestone **must not** ship assuming only client-driven `completed` sessions.

Extraction eligibility query (canonical):

```sql
WHERE status IN ('completed', 'abandoned')
  AND deleted_at IS NULL
  AND (last_extracted_turn IS NULL OR last_extracted_turn < turn_count)
```

Index alignment: extend or replace the Phase 2 `idx_sessions_agent_extraction` predicate so both terminal statuses are covered (do not leave the index filtered to `completed` only).

---

## Deliverables

- Worker query / repository method that selects terminal sessions for an org/agent
- Incremental cursor update after successful turn extraction
- Integration test: abandoned session (sweeper path) is extracted the same as completed
- Document that `active` sessions are never extracted

---

## Acceptance Criteria

- [ ] Extraction queries `status IN ('completed','abandoned')` (not `completed` alone)
- [ ] Hard dependency on [2.4.4](/roadmap/phase-2-single-provider/milestones/2.4.4-session-idle-timeout-sweeper) called out in PR and docs
- [ ] Abandoned session produces extractable turns in integration test
- [ ] Read pointer advances; re-run does not re-extract the same turns
- [ ] Active sessions are skipped
