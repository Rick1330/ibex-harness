## Why This Milestone Exists

Embedding the same text repeatedly is expensive (GPU time or API cost) and unnecessary. A content-hash cache using `SHA-256(text) → vector` in Redis sits in front of whichever `EmbeddingBackend` is active — backend-agnostic, no logic duplication per backend.

Memory content is often highly repetitive — the same user preference, factual statement, or procedural note gets re-embedded each time it's updated or re-ranked. A `>80%` hit rate target is realistic and materially reduces both latency and cost.

## Design

The cache is a decorator over `EmbeddingBackend`:

```python
# Illustrative — exact path may differ
import hashlib
import redis.asyncio as redis
import numpy as np
from .backends.base import EmbeddingBackend

class CachingEmbeddingBackend(EmbeddingBackend):
 """Wraps an EmbeddingBackend with a Redis content-hash cache.

 Key format: embed:{model_id}:{sha256(text)}
 TTL: configurable, default 7 days
 """
 def __init__(self, backend: EmbeddingBackend, redis_client: redis.Redis,
 model_id: str, ttl_seconds: int = 604800):
 self._backend = backend
 self._redis = redis_client
 self._model_id = model_id
 self._ttl = ttl_seconds

 async def embed(self, texts: list[str]) -> np.ndarray:
 keys = [self._cache_key(t) for t in texts]
 cached = await self._redis.mget(keys)
 results = [None] * len(texts)
 miss_indices = []

 for i, val in enumerate(cached):
 if val is not None:
 results[i] = np.frombuffer(val, dtype=np.float32)
 else:
 miss_indices.append(i)

 if miss_indices:
 miss_texts = [texts[i] for i in miss_indices]
 miss_vectors = await self._backend.embed(miss_texts)
 pipe = self._redis.pipeline()
 for idx, vec in zip(miss_indices, miss_vectors):
 results[idx] = vec
 pipe.setex(keys[idx], self._ttl, vec.tobytes())
 await pipe.execute()

 return np.stack(results)

 def _cache_key(self, text: str) -> str:
 h = hashlib.sha256(text.encode()).hexdigest()
 return f"embed:{self._model_id}:{h}"

 @property
 def dimensions(self) -> int:
 return self._backend.dimensions

 @property
 def name(self) -> str:
 return f"cached:{self._backend.name}"
```

## Redis Key Pattern

| Component | Value |
| --- | --- |
| Prefix | `embed:` |
| Model ID | `bge-m3`, `all-MiniLM-L6-v2`, `text-embedding-3-large`, etc. |
| Content hash | `SHA-256(text)` hex |
| Full key example | `embed:bge-m3:a3f2e1...` |
| TTL | 7 days (configurable via `EMBEDDER_CACHE_TTL_SECONDS`) |

Changing the embedding model (profile upgrade) naturally invalidates all cache entries because `model_id` is part of the key — no explicit flush required.

## Success signals

Outcome-oriented signals that the milestone is in good shape. Exact filenames, package layouts, and commands may differ from any sketches above.

- [ ] Relevant behavior wraps any `EmbeddingBackend`, transparent to callers
- [ ] Cache key uses `SHA-256(text)` with model ID prefix (not text content in key)
- [ ] Cache hit: no call to underlying backend
- [ ] Cache miss: underlying backend called, result stored with TTL
- [ ] Batch requests: mixed hit/miss handled efficiently (single `MGET`, one pipeline `SETEX` batch)
- [ ] TTL configurable via `EMBEDDER_CACHE_TTL_SECONDS` env var, default 7 days
- [ ] Cache hit/miss rate exposed as Prometheus counter (labels: `backend`, `hit=true|false`)
- [ ] Unit tests cover hit, miss, partial-batch, and Redis failure (fail-open: on Redis error, call backend directly)
- [ ] Redis failure does not fail the embedding request
