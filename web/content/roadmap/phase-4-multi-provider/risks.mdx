# Phase 4 — Risks and Mitigations

<Callout type="note" title="Risk ownership">
  Track P turns architectural risks into acceptance gates. A risk is not mitigated by prose alone; the owner must attach contract, test, operational, and rollback evidence to the milestone that closes it.
</Callout>

| Risk | Area | Likelihood | Impact | Mitigation and evidence |
|---|---|---:|---:|---|
| The static documentation deployment is mistaken for a dashboard runtime. | 4.P.0 | High | Critical | Choose and deploy a server-capable operator topology or a separate SPA/API/SSE origin. Verify cookies, CORS/CSRF, stream reconnect, health, readiness, drain, and rollback. |
| Cross-tenant data leaks through IDs, caches, queues, exports, or analytical stores. | 4.P.1 | Medium | Critical | Derive tenant context server-side, enforce policy on every path, use anti-enumeration responses, and run two-tenant negative matrices across synchronous and asynchronous flows. |
| Raw prompts, outputs, or tool arguments leak into logs, traces, dead letters, exports, or the browser. | 4.P.3 / D2–D4 | Medium | Critical | Redact before queueing, use metadata-only defaults, encrypt privileged payloads, escape untrusted rendering, audit raw access, and scan hostile-content fixtures. |
| Aggregate traces cannot explain why a decision occurred. | 4.P.2 / D2 | High | Critical | Establish canonical nested evidence with stable IDs, parent/links, sequence, checkpoint joins, provenance, completeness, sampling, and durable publication before Trace Inspector release. |
| At-least-once event delivery creates duplicate or reordered evidence. | 4.P.2 | Medium | High | Use transactional outbox, idempotent consumers, aggregate sequence, dedupe keys, replay tests, poison-message handling, and explicit late/partial states. |
| Realtime streams lose events or exhaust memory under slow clients. | 4.P.0 / C.5 / E.2 | Medium | High | Bound buffers, publish resume positions, use `Last-Event-ID`, measure lag and memory, disconnect slow clients safely, and test provider/queue failure. |
| Retention TTL is treated as coordinated deletion. | 4.P.3 | High | Critical | Use policy records, tombstones, legal holds, per-store watermarks, receipts, idempotent purge, and deletion verification across every store and derived projection. |
| Usage/cost charts double count retries, fallbacks, or late events. | 4.P.4 / D6 | Medium | High | Use immutable usage facts, rate-card versions, idempotency, reconciliation reports, freshness/completeness indicators, and hard-cap negative tests. |
| A budget or capacity control is advisory when it must deny traffic. | B / P4 / D6 | Medium | Critical | Keep enforcement on the proxy path, reconcile Redis with durable facts, test concurrent over-admission, and stage soft then hard limits with a kill switch. |
| Replay or policy actions mutate production state unexpectedly. | D3 / D5 | Medium | Critical | Use immutable snapshots, sandboxed or mocked tools, preview/dry-run, step-up/dual approval, action ledger, idempotency, blast-radius display, and rollback pointers. |
| Directive/routing changes have no reproducible provenance. | C / D5 | Medium | High | Record policy/directive/capability versions, input hashes, candidates, rejection reasons, approvals, exposure, evaluation, and rollback pointer. |
| Drift alerts are built before their producer, baseline, and evaluation contracts exist. | D5 / Phase 4.5 | High | Medium | Keep drift integration behind a contract gate; deliver directive/routing controls first and add alert views only after Phase 4.5 producer evidence exists. |
| Backup restore does not preserve evidence or tenant isolation. | P5 / E2 | Medium | Critical | Define RPO/RTO, cover Postgres, ClickHouse, Redis, object manifests, and outbox, run clean restore drills, and test tenant isolation after restore. |
| Supply-chain compromise reaches the operator runtime. | P5 | Low | Critical | Pin image digests, generate SBOM/provenance, sign artifacts, verify admission, scan dependencies, and record deploy identity in the evidence bundle. |
| Accessibility or data-state defects make the dense investigation UI unusable. | D1–D6 / P6 | Medium | High | Require keyboard and screen-reader checks, axe, semantic tables, visible focus, loading/empty/error/partial/stale states, and four-role Playwright journeys. |
| Query cost or cardinality degrades the operator platform. | P4 / D2 / D6 | Medium | High | Use bounded grammar, filter-before-page, cursor pagination, query budgets, high-cardinality-safe dimensions, EXPLAIN review, p95/p99 budgets, and rate limits. |
| Release evidence is incomplete but rollout proceeds. | P6 / E1–E4 | Medium | Critical | Make contracts, security, privacy, accessibility, performance, recovery, supply-chain, and rollback evidence required promotion inputs. Zero open P0 findings is mandatory. |

## Escalation policy

Any tenant-isolation, secret exposure, deletion-integrity, unsafe-action, restore-integrity, or supply-chain failure is a P0 release blocker. The rollout must stop, the affected capability must be disabled, and the incident must receive an evidence bundle. P1 risks require an owner and dated remediation before default-on. P2 risks require a documented acceptance or follow-up milestone.
