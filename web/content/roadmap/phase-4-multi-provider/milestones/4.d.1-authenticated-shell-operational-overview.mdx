# Milestone 4.D.1 — Authenticated Shell & Operational Overview

**Status:** Planned  
**Outcome:** An authorized operator enters a real application, selects an organization, sees platform health/freshness, and reaches every investigation surface.  
**Track:** [Track D — Operator Capability Slices](/roadmap/phase-4-multi-provider/tracks#track-d--operator-capability-slices)  
**Dependencies:** Track P gates  
**Estimated effort:** 3 weeks

<Callout type="note" title="Completion contract">
  This milestone is complete only when the implementation, versioned contract, verification evidence, operational signals, and rollback behavior described below are present. A mock screen, planning-only schema, permission constant, or passing unit test alone is not sufficient evidence.
</Callout>

## Why this milestone exists

An authorized operator enters a real application, selects an organization, sees platform health/freshness, and reaches every investigation surface.

## Scope and deliverables

Build operator app shell, org/role context, Overview, Agents/Resources, Explore, Incidents, Settings, breadcrumbs, global search entry, live/historical selector, connection state, and data-state components.

## Contract and data requirements

Consume generated SDK only. URL state stores org, time range, filters, columns, and selected resource.

## Product and UX requirements

Provide clear empty/error/partial/stale/degraded states and keyboard navigation.

## Non-functional requirements

Four roles, two tenants, initial-read budget, axe, keyboard, no-cross-tenant, and SSE reconnect gates pass.

## Verification gates

Internal allowlist and read-only flag. Disable route access independently.

## Rollout and rollback

Creates the first end-to-end operator proof on top of Track P. **Trigger:** shell auth, org scope, or Overview health regressions in staging. **Reversal:** disable the operator shell or individual routes independently behind the allowlist/read-only flag without changing Track P data. **Verify:** public docs remain available; login and deep links fail closed; recovery restores Overview and navigation after the flag is cleared.

## Findings addressed

This milestone addresses the repository and roadmap findings recorded in Track P and the Phase 4 findings register.

## Exit checklist

- [ ] Performance, accessibility, failure, and rollback evidence is attached to the milestone record.
- [ ] Documentation, runbooks, and links are updated before the milestone is marked complete.
