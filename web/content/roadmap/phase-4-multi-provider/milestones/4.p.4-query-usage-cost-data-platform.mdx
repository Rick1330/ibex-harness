# Milestone 4.P.4 — Query, Usage & Cost Data Platform

**Status:** Planned  
**Outcome:** Dashboard reads are bounded and explainable, and usage/cost facts can safely drive policy.  
**Track:** [Track P — Operator Readiness, Evidence & Control Plane](/roadmap/phase-4-multi-provider/tracks#track-p--operator-readiness-evidence--control-plane)  
**Dependencies:** 4.P.2; 4.P.3 (capture/redaction defaults)  
**Estimated effort:** 4 weeks  
**Gate:** part of post-P.3 parallel track with 4.P.5 / 4.P.6

<Callout type="note" title="Completion contract">
  Charts over request counts are not cost governance. Every ClickHouse query shape requires an explicit `org_id` parameter and predicate.
</Callout>

<Callout type="info" title="Planning baseline (sketch deviations)">
  Locked for implementation (4.P.4):

  - **Hybrid ledger:** ClickHouse `ibex.usage_facts` (immutable per-call facts) + Postgres `ibex_billing` (rate cards, budget periods, enforcement decisions).
  - **No TTL** on `usage_facts` (indefinite retention; explicit ops purge later) — matches billing retention carve-out.
  - **Write-time freeze:** `estimated_cost_cents` + `rate_card_version` frozen at enqueue; `actual_cost_cents` only via worker reconciliation (stubbed until invoice source exists).
  - **Spend caps fail-closed** via `packages/billing` cache (`budget_updates:{org_id}`); proxy `BudgetMiddleware` returns **402 `BUDGET_EXCEEDED`**. RPM / `packages/ratelimit` fail-open is untouched.
  - **Typed usagequery AST** in Go (`packages/usagequery`); Python Management API executes constrained SQL templates kept in sync via golden fixtures.
  - **Org deletion** does **not** erase CH `usage_facts` or PG billing rows (SECURITY.md billing carve-out).
  - **Deferred:** OpenAI-compat non-stream `Usage` unset (tracked separately); Track D UI / 4.P.5 / 4.P.6 out of scope.
</Callout>

## Why this milestone exists

Ad hoc client filtering cannot scale; billing schema was falsely assumed to exist (F4-005).

## Scope and deliverables

- Shared query grammar: typed fields, operators, time range, facets, autocomplete, saved-view URL serialization, cursor pagination, query budgets.
- ClickHouse shapes for org/time, agent/session, event point lookup, run reconstruction, tool correlation, cost aggregation — **each with mandatory `org_id`**.
- Immutable usage ledger facts keyed by `org_id`, agent, provider, model, run, time, token class, tool units, latency, status, fallback, rate-card version, policy version.
- Versioned rate cards, currency, estimate/actual, budget periods, alerts, reconciliation jobs, enforcement decision records.

## Contract and data requirements

Filters apply before pagination. High-cardinality IDs remain event fields, not metric labels. Freshness/completeness fields on every aggregate response.

## Product and UX requirements

UI labels live vs retained data, ingestion lag, retention boundary, matched vs displayed/sample counts, cost source facts, rate-card and policy versions.

## Non-functional requirements

EXPLAIN review, p95/p99 query targets, bounded memory, sampling-bias disclosure, aggregate-to-raw reconciliation, duplicate-retry billing tests, hard-cap denial tests.

## Verification gates

Query contract suite, EXPLAIN samples, reconciliation report, fallback attribution, rate-card replay, hard-cap negative path on proxy.

## Rollout and rollback

**Trigger:** hard-cap false positives/negatives, reconciliation drift, or query SLO breach. **Reversal:** revert hard-cap enforcement to alert-only; preserve immutable facts; roll back rate-card/policy version. **Verify:** alert-only still emits; reconcile outstanding decisions before re-enabling hard caps.
