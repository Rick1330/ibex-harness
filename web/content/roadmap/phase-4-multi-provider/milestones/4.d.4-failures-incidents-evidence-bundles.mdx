# Milestone 4.D.4 — Failures, Incidents & Evidence Bundles

**Status:** Planned  
**Outcome:** An operator triages a failure, assigns ownership, preserves evidence, and produces a postmortem-ready bundle.  
**Track:** [Track D — Operator Capability Slices](/roadmap/phase-4-multi-provider/tracks#track-d--operator-capability-slices)  
**Dependencies:** 4.D.2; 4.P.2 events; 4.P.3 audit/evidence bundle; 4.P.4 query  
**Estimated effort:** 3 weeks

<Callout type="note" title="Completion contract">
  The insert-only `failed_tasks` table is ingestion/forensics data, not an incident workflow.
</Callout>

## Why this milestone exists

Ninety-day metadata alone cannot support high-quality postmortems.

## Scope and deliverables

Failure projection distinct from `failed_tasks`; incident state machine; severity, owner, assignment, dedupe key, timeline; linked traces/sessions/requests; redacted evidence; comments/activity; signed bundle export. Notifications are a later integration.

## Contract and data requirements

Every transition idempotent and audited. Raw traceback gated. Bundle reconstructs evidence after normal telemetry expiry without secrets or cross-tenant data.

## Product and UX requirements

Filters by status/severity/owner/time. Safe rendering of failure payloads (F4-008).

## Non-functional requirements

Action ledger for assignment/state; history not deleted on rollback.

## Verification gates

Idempotent transitions; bundle export reconstructs golden incident; cross-tenant isolation; hostile payload render.

## Rollout and rollback

**Trigger:** incident write-path regressions or evidence-bundle integrity failures. **Reversal:** return incident workflows to read-only triage; stop mutating incident state. **Verify:** existing bundles remain readable; no new write actions succeed until rollback cleared.

## Findings addressed

F4-008, F4-011.

## Exit checklist

- [ ] Incident state machine + audit evidenced.
- [ ] Signed evidence-bundle demo attached.
- [ ] Read-only rollback path demonstrated.
