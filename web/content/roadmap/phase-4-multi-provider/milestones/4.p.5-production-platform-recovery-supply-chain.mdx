<Callout type="info" title="Locked decisions (4.P.5)">
  - **Helm only** (`infra/helm/ibex-harness/`); no Kustomize.
  - **Backup:** pgBackRest → MinIO (simulated off-cluster; values swap for real S3).
  - **Drill:** kind/k3d + compose data plane; transcript attached to PR.
  - **RPO/RTO:** Postgres ≤5m / ≤30m; ClickHouse ≤24h / ≤60m; Redis none (cache); MinIO ≤24h / ≤60m; outbox RPO=0 via `MAX(aggregate_seq)`.

  - **Worker limits:** rollup 60/120s; reconcile 300/600s; maintenance 300/600s.
</Callout>

## Why this milestone exists

Without deploy/recover/admit evidence, Track D cannot be production-ready.

## Scope and deliverables

- Helm overlays for proxy, auth, api, worker, memory, embedder, mcp-memory (`infra/helm/ibex-harness/`).
- Digest-pinned images; startup/liveness/readiness probes (ADR-0022); PDBs; HPA; migration Job hook; rolling update with progress deadline abort; rollback-by-digest runbook.
- Encrypted MinIO-backed pgBackRest; restore + evidence-bundle recover scripts; backup freshness Prometheus rules; measured RPO/RTO in restore-drill report.
- Cosign image-digest signing (extends `docker-publish.yml`); Kyverno `verifyImages` policy; `evidence_runs.deploy_image_digest`.
- Worker soft/hard time limits for billing reconcile + maintenance (F4-020 residual).
- Operator platform health: `GET /v1/operator/platform/health`.

## Contract and data requirements

Operators can query dependency health, last backup, last restore drill, retention horizon, ingestion lag, DLQ depth, degraded-mode state via `/v1/operator/platform/health`.

## Product and UX requirements

Overview surfaces platform health/freshness inputs consumed by 4.D.1.

## Non-functional requirements

Load and chaos: peak+headroom, Redis/ClickHouse/Postgres degradation, provider failure, slow consumers, queue saturation, rollback. SLOs: latency percentiles, availability, error rate, throughput, queue lag, cost budgets.

## Verification gates

Clean-environment restore meets RPO/RTO and preserves tenant isolation. Admission rejects unsigned/wrong-digest images in staging.

## Rollout and rollback

**Trigger:** failed restore, probe failure, or admission mismatch. **Reversal:** roll back by digest and known-good migration-compatible version; never roll back a migration without its compatibility procedure. **Verify:** restore drill report + canary abort transcript attached. Runbook: `web/engineering/runbooks/RUNBOOK-4p5-rollback-by-digest.md`.
