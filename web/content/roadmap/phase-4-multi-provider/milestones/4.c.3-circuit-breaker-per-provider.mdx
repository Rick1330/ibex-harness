## Why This Milestone Exists

The architecture explicitly requires circuit breakers on provider and context dependencies. A breaker trips independently per provider name — Anthropic outage should never degrade OpenAI traffic. Uses a rolling error-rate window (last 30s, min 10 samples, &gt;50% failure trips open) rather than naive consecutive-failure counting, which is too sensitive to flapping.

## Design note: Rolling Error-Rate Window

Use a rolling error-rate window (e.g., last 30s, min 10 samples, &gt;50% failure trips open) rather than "5 consecutive failures" — consecutive-count breakers are too sensitive to single flapping request patterns and too slow to trip under genuine partial degradation. The breaker state machine follows the glossary definition: closed → open → half-open.
