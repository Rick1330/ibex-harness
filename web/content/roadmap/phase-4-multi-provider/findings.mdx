# Phase 4 — Findings Register

<Callout type="note" title="How to read this register">
  These findings are roadmap constraints derived from repository inspection and product design review. They are not claims that a future contract is already implemented. Each finding is mapped to a milestone that must produce verification evidence before it can be closed.
</Callout>

## Executive finding

The original Phase 4 plan was a minimal feature list. It described screens and endpoints but did not define the runtime, evidence graph, privacy lifecycle, tenant policy, query semantics, durable usage facts, recovery model, or executable release gates required for a world-class operator product. The redesign therefore places readiness and control-plane work before dashboard UI and treats each capability as a vertical slice with contract and assurance evidence.

## Findings and disposition

| ID | Finding | Severity | Disposition |
|---|---|---:|---|
| F4-001 | The public web deployment is static documentation output and cannot provide cookie-backed dynamic dashboard behavior or a long-lived SSE endpoint by itself. | P0 | Resolve in 4.P.0 with an explicit server-capable or SPA/API/SSE topology. |
| F4-002 | Dashboard identity, org switching, resource authorization, step-up assurance, and asynchronous-job scope were not a single enforceable contract. | P0 | Resolve in 4.P.1 with deny-by-default policy and negative isolation matrices. |
| F4-003 | Aggregate trace rows cannot explain nested causality, checkpoint joins, candidate ranking, fallback, tool, or evaluation provenance. | P0 | Resolve in 4.P.2 with canonical trace/span/event contracts and durable publication. |
| F4-004 | ClickHouse TTL and browser confirmation are not coordinated deletion, legal hold, or data-subject erasure. | P0 | Resolve in 4.P.3 with tombstones, store watermarks, receipts, and audit. |
| F4-005 | The old cost milestone assumed durable usage and billing facts that were not defined at the required org/agent/provider/model scope. | P1 | Resolve in 4.P.4 and 4.D.6 with immutable usage facts, rate-card versions, reconciliation, and enforcement. |
| F4-006 | Generic permission constants do not define raw-data, export, deletion, replay, policy-change, secret-use, or break-glass authorization. | P0 | Resolve in 4.P.1 and 4.P.3 with resource/field/action policy. |
| F4-007 | Realtime streams need durable positions, resume semantics, bounded buffers, dedupe, and partial-data states. | P1 | Resolve in 4.P.2 and verify through 4.E.2 slow-client and reconnect tests. |
| F4-008 | Prompts, outputs, tool arguments, links, HTML, and Markdown are untrusted data and must never become browser actions or unsanitized markup. | P0 | Resolve in 4.P.3 and 4.D.2–4.D.4 safe-rendering tests. |
| F4-009 | The previous Trace Inspector did not separate score contribution, rank transition, resource cost, and selection outcome. | P1 | Resolve in 4.D.2 and the UI/UX investigation standard. |
| F4-010 | Replay, counterfactuals, policy changes, and fallback are high-impact actions without a common preview, approval, ledger, and rollback contract. | P0 | Resolve in 4.P.1, 4.P.2, and 4.D.5. |
| F4-011 | Backup/restore, RPO/RTO, rollout abort, image provenance, and admission checks were described but not required release evidence. | P0 | Resolve in 4.P.5 and 4.E.2–4.E.3. |
| F4-012 | Existing dashboard E2E planning did not prove four roles, two tenants, accessibility, hostile-content rendering, or static-site/runtime separation. | P1 | Resolve in 4.P.6 and 4.E.1. |
| F4-013 | Drift and directive management were combined without an explicit producer contract for fingerprints, baselines, evaluations, or alert lifecycle. | P1 | Keep directive/routing controls in 4.D.5; integrate drift only after Phase 4.5 producer contracts are published. |
| F4-014 | Documentation status did not expose the redesigned Phase 4 milestone graph or active work state. | P1 | Resolve in the Phase 4 index, current-state page, tracks, goals, risks, and this register. |

## Closure rule

A finding is closed only when the referenced milestone has a merged implementation or accepted contract, a reproducible verification artifact, an owner, and an operational rollback or residual-risk decision. A roadmap page alone is evidence of intent, not closure.
