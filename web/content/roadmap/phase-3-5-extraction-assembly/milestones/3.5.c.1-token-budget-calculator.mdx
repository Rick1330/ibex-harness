## Why This Milestone Exists

Every downstream stage in context assembly depends on knowing the usable token budget for the *specific* model being called. Phase 2.5 already curates that metadata in Go (`BuiltInCapabilityCatalog`). This milestone wires Python budget math to that catalog **without** inventing a live tokenizer/capability RPC (reserved for 3.5.C.6).

There is **no** `TokenizerClient` or network `CapabilityRegistry` in C.1. The catalog is the committed generate-and-diff artifact of `packages/provider.BuiltInCapabilityCatalog`.

---

## Design note

Safety buffers are **tokenizer-family-specific fractions** from the export (`o200k_base`/`cl100k_base` 2%, `claude` 5%, `unknown` 10%), not a flat 10% guess. Token counts are **labeled approximations** (`estimate_kind` on every `TokenBudget`) until [#690](https://github.com/Rick1330/ibex-harness/issues/690) lands exact backends.

**Failure mode:** unknown model IDs raise `UnknownModelError` (fail closed). Estimates always run locally — there is no “tokenizer unreachable” network path in C.1.
