## Why This Milestone Exists

Parseability checks do not measure extraction correctness. This milestone is the extraction-side counterpart to Phase 3 retrieval-quality gating ([ADR-0061](/docs/adr/0061-retrieval-quality-benchmark-methodology)).

---

## Non-Goals

- Real-time extraction quality monitoring in the operator dashboard (Phase 4)
- A/B testing infrastructure for prompt variants
- GPU CI runners (still none — mirrors 3.5.B.2)

---

## Design (as implemented)

Layout: [`services/worker/eval/`](/services/worker/eval) with versioned [`gold_set/v1/`](/services/worker/eval/gold_set/v1).

| Decision | Choice |
| --- | --- |
| vLLM side-by-side | **Path (a):** CI OpenAI only; vLLM `enforcement: manual` in baseline + runbook |
| Live vs cassette | Hybrid: PR/smoke/fast = cassette ($0); full = optional live OpenAI |
| Gate | Absolute **3pp** on CI-enforced metrics; exit code 1 (unit-tested) |
| Publish | `web/public/benchmarks/extraction-quality-benchmark-data.json` + bot suite |

See [ADR-0066](/docs/adr/0066-extraction-quality-evaluation-harness) and the gold-set [README](/services/worker/eval/gold_set/v1/README.md).
