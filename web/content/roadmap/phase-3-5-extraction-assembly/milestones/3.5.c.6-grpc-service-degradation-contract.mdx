## Why This Milestone Exists

Wraps Track C’s budget/retrieval/scorer/packer/formatter into `ContextAssemblyService.AssembleContext` and locks operational degradation (L0–L2 in-service; L3 as proxy fail-open on `DEADLINE_EXCEEDED`).

## File layout (as shipped)

```
services/context/app/assemble.py              # ContextAssembler, L0–L2 classification
services/context/app/server.py                # grpc.aio AssembleContext + UNIMPLEMENTED stubs
services/context/app/__main__.py              # python -m app

```

Settings / env:

- `IBEX_CONTEXT_DEADLINE_MS` (default `40`) — retrieval wall; effective wait `min(timeout_ms, deadline_ms)`
- `IBEX_CONTEXT_GRPC_ADDR` (default `127.0.0.1:9092`) — bind address

---

## Degradation Ladder (as shipped)

| Level | Trigger | Behavior | Signal |
|---|---|---|---|
| L0 — Full | Hot + cold usable (or intentional skips) | Full pack/format | `degradation_level=L0` (debug); memories from both |
| L1 — Cold degraded | Cold timeout/error | Hot (+ directive) only | INFO log; hot-only `candidates_evaluated` |
| L2 — Memory degraded | Hot and cold both fail | Directive + history only | INFO log; `memories_included==0` |
| L3 — Full degraded | Caller cancel / deadline | No partial invent | gRPC `DEADLINE_EXCEEDED` → proxy fail-open (**3.5.D.1**) |

No new proto response fields — observability via `AssemblyMetrics` + structured logs ([ADR-0071](/docs/adr/0071-context-grpc-degradation-deadline)).
