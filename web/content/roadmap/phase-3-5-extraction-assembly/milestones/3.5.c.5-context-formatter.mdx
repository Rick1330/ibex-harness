## Why This Milestone Exists

Memories are untrusted input and must be wrapped as data with a per-assembly nonce ([SECURITY.md](/engineering/SECURITY) §7.3). Conversation history is trusted and must stay as native role messages. Planning docs disagreed on history position; this milestone locks order in code + ADR and corrects ARCHITECTURE.md’s stale “history last” line.

## Final Locked Ordering

```
1. Directive (always first — sets behavior before any content)
2. Conversation history (native role: content lines — not XML-wrapped)
3. Memories by category (procedural → factual → preference → behavioral → episodic)
4. Tool schemas (if applicable)
```

**Rationale for History in position 2:** “lost in the middle” — history stays near the start where attention is reliable.

Memory wrap:

```text
<ibex_memory nonce="{nonce}" id="{memory_id}" category="{category}">
{content}
</ibex_memory>
```
