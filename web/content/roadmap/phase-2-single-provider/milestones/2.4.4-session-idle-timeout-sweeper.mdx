## Why This Milestone Exists

[2.4.2](/roadmap/phase-2-single-provider/milestones/2.4.2-session-store) defines `SessionStore.Complete()` when the client sends `X-IBEX-Session-End: true` **or** after a configurable idle timeout. No milestone implemented the idle path. Real clients rarely send end-of-session headers. Without a sweeper, sessions stay `active` forever and Phase 3 extraction (`WHERE status = 'completed'`) never runs — shipping all of Phase 3 would still leave memory extraction dead in production.

This is the concrete form of the missing **Garbage Collection Worker** in [ARCHITECTURE.md](/docs/engineering/ARCHITECTURE) (background workers).

---

## Decision

Implement a **lightweight ticker in the Go proxy** (no Celery required at Phase 2/3 scale):

1. Every `IBEX_SESSION_SWEEP_INTERVAL` (default 1m), query sessions with `status = 'active'` and `updated_at < now() - IBEX_SESSION_IDLE_TIMEOUT` (default 45m).
2. Mark them `status = 'abandoned'` via `SessionStore` (org-scoped updates).
3. Treat `abandoned` the same as `completed` for extraction eligibility in 3.4.2.

Env vars (document in `.env.example` + ENVIRONMENT_VARIABLES.md when implemented):

- `IBEX_SESSION_IDLE_TIMEOUT` — duration string, default `45m`
- `IBEX_SESSION_SWEEP_INTERVAL` — duration string, default `1m`
