## What Ships Today

<Callout type="note" title="Current capability boundary">
  Authenticated request handling and governance are production-ready. OpenAI JSON
  and SSE forwarding ship when `IBEX_LLM_MODE=live` and `OPENAI_API_KEY` are set
  (default `mock` keeps `501 PROVIDER_NOT_CONFIGURED`). Provider routing middleware
  (2.1.4) selects the adapter from the request model; provider failures map to the
  stable IBEX envelope (2.1.5). The memory pipeline is
  deferred until Phase 3; multi-provider routing remains out of scope until Phase 4.
</Callout>

### Platform (Phase 1)

- Auth gRPC (`ValidateToken`, `ValidateAgent`) with Argon2id-backed token validation
- Proxy auth middleware, agent verification, request normalization, stable error envelopes, rate limiting
- Security integration gate with 31-case cross-tenant denial matrix and CI enforcement
- Shared packages (`logger`, `metrics`, `telemetry`, `config`, `apierror`, `shutdown`, `reqid`, `ratelimit`, `crypto`, `permissions`, `provider`)
- Postgres migrations with RLS; integration smokes for auth, proxy, and security paths

## Blockers And Risks

<Callout type="warning" title="Phase 2 entry">
  Non-streaming and streaming OpenAI forwarding ship when `IBEX_LLM_MODE=live` and `OPENAI_API_KEY` are set
  (`stream=false` JSON or `stream=true` SSE per [ADR-0026](/docs/adr/0026-openai-client-design) and
  [ADR-0027](/docs/adr/0027-streaming-dual-write)). Default `IBEX_LLM_MODE=mock` keeps
  `501 PROVIDER_NOT_CONFIGURED` for CI and local dev without a provider key.
</Callout>

- Python services (memory, context, embedder, worker, api, dashboard) are not in shipping scope until Phase 3
- Phase 2.6.1 latency benchmark infrastructure exists (Phase 1.5 pre-work); Phase 2 middleware-complete baseline still required
