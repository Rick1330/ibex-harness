# G0 Owner Decision Recommendations

**Status:** `proposed` — review worksheet only. This is not an ADR, accepted contract, owner attestation, supported-profile declaration, or implementation authorization.

**Audit baseline:** main `7298e5ee7982b926630566c88830c99650c8eb37`; the recommendations are based on architecture-v2 and the source-audit bundle indexed in [`web/engineering/research/ibex-preflight-2026-10/`](../research/ibex-preflight-2026-10/README.md). The implementation branch contains the documentation checkpoint; this file does not change runtime behavior.

**Purpose:** turn the open decisions in the [70-criterion synthesis](20-pre-g0-gap-synthesis-and-workplan.md) into concrete defaults for owner review. Where the source of truth lacks the information needed for a safe default—such as a legal retention period, production profile, owner name, or numerical RPO/RTO—the recommendation is to keep the capability unaccepted rather than invent a value.

## Decision rule

Every item below remains **proposed** until the accountable owner, independent reviewer, and evidence owner approve it for a named profile and the decision is recorded in [`00-status-and-evidence.md`](00-status-and-evidence.md). A repository merge, user instruction to continue, issue closure, or passing local unit test is not a substitute for decisions delegated to Security, Privacy/Legal, Finance, or Operations. If owners do not decide, preserve the present fail-closed/unknown boundary and do not implement or advertise the capability as accepted.

## Decisions that cannot be responsibly inferred

The following are intentionally **not assigned** by this proposal: accountable individual names and independent reviewers; the first production deployment profile; data residency/jurisdiction; retention durations and legal-hold rules; financial overage and reconciliation policy; exact provider/model/region support; whether protected-profile MCP writes are allowed; numerical RPO/RTO and uptime commitments; and production support/escalation ownership. Choosing these affects permissions, money, privacy, reliability commitments, or user-visible behavior. A role label is not a named accountable owner.
