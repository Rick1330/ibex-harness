## Follow-ups

### Finding — GAP-005/GAP-011 relay payload integrity and acknowledgement-loss evidence

- **Reproducible steps:** Construct or retrieve an outbox row whose `payload_digest` is a well-formed 64-character hexadecimal string for different bytes; or deliver a claimed row successfully and lose the `mark_delivered` acknowledgement before replaying it.
- **Expected:** The relay rejects tampered digests, unclassified/redacted/prohibited rows, and missing-fence/no-hook cases before sink delivery; after acknowledgement loss, tenant-scoped `(org_id, event_id, aggregate_seq)` replay produces one externally applied effect.
- **Actual:** The relay verifies digest equality and rejects unclassified, redacted, prohibited, unsupported, and missing/invalid-fence rows or sinks without the typed fence-aware hook. PR C adds `SanitizeRunInput`, which copies only versioned metadata fields and downgrades/withholds unsafe or incomplete rows; the proxy attaches a fence read from the active PostgreSQL session row. Migration 000041 advances the session fence atomically with soft deletion. Migration 000042 persists only model ID and numeric token totals, with the existing JCS path digest-covering these values in the run-committed outbox event. The typed acknowledgement adapter maps durable/replayed to 200, proven degraded retry to 202, and failed/unknown/unproved outcomes to 503 `EVIDENCE_UNAVAILABLE`. However, the chat/session finalizer still persists after its response, so it cannot make that response contingent on evidence.
- **Source:** `packages/evidenceoutbox/types.go`, `store.go`, `relay.go`, `reconcile_store.go`, `relay_unit_test.go`, `store_unit_test.go`, and `store_integration_test.go`; sanitizer at `services/proxy/internal/http/session/evidence/sanitize.go`; producer/finalizer at `services/proxy/internal/http/session/evidence.go` and `snapshot.go`; fence source at `packages/session/evidence_fence.go`; acknowledgement adapter at `services/proxy/internal/http/session/evidence_ack.go`. Migrations 000041 and 000042 add the session lifecycle version and safe run metadata fields.
- **Impact / severity:** Evidence integrity and recovery accounting risk; **P1** for protected evidence profiles.
- **Profile:** PostgreSQL evidence/outbox relay; local integration profile only. Hosted/HA profiles are not certified.
- **Evidence:** All eight PostgreSQL-backed evidenceoutbox integration tests passed against the local Podman test database on 2026-10-14 after PR #975, including persistence, replay, tenant RLS, role restrictions, and durable poison transitions; the ClickHouse integration test was skipped. The unit suite also passed. These are local tests, not hosted/HA recovery or G4 sink evidence.
