## Follow-ups

### Finding — GAP-005/GAP-011 relay payload integrity and acknowledgement-loss evidence

- **Reproducible steps:** Construct or retrieve an outbox row whose `payload_digest` is a well-formed 64-character hexadecimal string for different bytes; or deliver a claimed row successfully and lose the `mark_delivered` acknowledgement before replaying it.
- **Expected:** The relay rejects tampered digests, unclassified/prohibited rows, and missing-fence/no-hook cases before sink delivery; after acknowledgement loss, tenant-scoped `(org_id, event_id, aggregate_seq)` replay produces one externally applied effect.
- **Actual:** The relay verifies digest equality and rejects unclassified, prohibited, unsupported, and missing/invalid-fence rows or sinks without the typed fence-aware hook. PR #975 validates producer metadata and matches its class/fence fields, but this does not sanitize or inspect payload content. The session producer can carry explicit `ProducerMetadata`, yet the current production call site does not set it; the deferred write therefore remains unclassified/fenceless and relay delivery fails closed. `EvidenceAckProfile`/`EvidenceAckHTTP` helpers exist, but the current session flow is post-response and does not make that response contingent on durable evidence.
- **Source:** `packages/evidenceoutbox/types.go`, `store.go`, `relay.go`, `relay_unit_test.go`, `store_unit_test.go`, and `store_integration_test.go`; producer wiring in `services/proxy/internal/http/chat_context_assemble.go` and `services/proxy/internal/http/session/evidence.go`; acknowledgement helpers in `services/proxy/internal/http/session/evidence_ack.go`. Migration 000036 is unchanged; class/fence are Go/JSON payload metadata, not new SQL columns.
- **Impact / severity:** Evidence integrity and recovery accounting risk; **P1** for protected evidence profiles.
- **Profile:** PostgreSQL evidence/outbox relay; local integration profile only. Hosted/HA profiles are not certified.
- **Evidence:** All eight PostgreSQL-backed evidenceoutbox integration tests passed against the local Podman test database on 2026-10-14 after PR #975, including persistence, replay, tenant RLS, role restrictions, and durable poison transitions; the ClickHouse integration test was skipped. The unit suite also passed. These are local tests, not hosted/HA recovery or G4 sink evidence.
- **Owner:** Evidence/Operations + Platform/Data; Rick1330 acting owner across G0 roles; no independent reviewer named. G0 review/expiry: 2026-11-10.
- **Next action:** Keep fail-closed behavior. Wire only producer-authoritative, reviewed sanitizer/class proof and an authoritative resource/version source; then verify response-bound acknowledgement and durable reconciliation. Connect the fence to the authoritative PostgreSQL lifecycle table before enabling production projection. Do not infer class or tombstone from aggregate IDs or untyped JSON.
- **Status:** Producer-proof validation and fail-closed relay checks are locally verified; actual production producer injection, content sanitization, response-bound acknowledgement, authoritative fence integration, ClickHouse G4 adapter, and hosted recovery remain open. GAP-005 and GAP-011 remain open.

The Go envelope/store validates caller-supplied producer metadata and consistency of the declared fence, not whether content was in fact sanitized. No database migration or relay-role permission change is implied. No production sink or atomic delete-vs-project transaction is certified.

## Decisions needed before the next implementation slice

1. **Production evidence producer metadata and relay readiness (P1).** The store validates producer-supplied redaction/fence metadata, but the current session producer call site supplies none. No reviewed payload sanitizer or authoritative resource-version source is wired there. The post-response session write cannot certify durable-before-ack, even though acknowledgement helper functions exist. **Options:** (A) retain fail-closed behavior until producer-specific sanitation and lifecycle fencing are reviewed; (B) mark the current payload `metadata` and infer a fence from request/run IDs; (C) relax relay validation for legacy rows. **Recommendation:** A. Do not infer safety or deletion authority.
2. **Memory historical-mode internal boundary.** The dedicated `HistoricalConflictCapability` now binds org/agent and separates write-path historical search from ordinary user reads; persistence predicates also bind both IDs. `SearchMode` remains selectable by internal callers that can reach `VectorStore`. **Options:** (A) keep it package-internal, require the dedicated adapter, and audit direct callers; (B) hide mode selection behind a capability-only interface before broader use; (C) expose mode selection to external callers. **Recommendation:** A for current bounded usage with audit; B before broadening; C is rejected.
3. **PolicySnapshot runtime realization.** The authority and freshness envelope are accepted in decision 21 (AuthService signing-key set; immutable snapshot; 60-second protected-read/context, 30-second mutation/effect, five-minute async-continuation maximum ages, plus bounded clock skew). Runtime signature verification, key rollover, time-bound enforcement, and stale-denial tests are not complete. This is an implementation gate, not an unresolved choice of authority.
4. **Response-bound evidence acknowledgement.** The repository maps `EvidenceAckUnavailable` to HTTP 503 and `EvidenceAckUncertified` to HTTP 200 in a helper; the accepted owner contract permits `uncertified` only with durable reconciliation under a degraded profile. The post-response session writer is not a synchronous acknowledgement path, and the helper does not itself prove retry state is durable. **Decision before wiring:** verify operation/profile and durable reconciliation; otherwise required-evidence failure or unknown commit must not return success. Do not silently adopt 202 or another unapproved mapping.
