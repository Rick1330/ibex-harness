## Contract hierarchy

- **Protobuf/gRPC:** internal multi-consumer service contracts.
- **OpenAPI/REST:** external management and resource APIs under `/v1`.
- **Provider contracts:** separately versioned Chat Completions and Responses subsets plus native adapter semantics.
- **MCP schemas:** versioned tools/resources with explicit scopes and limits.
- **Events:** durable evidence and operation envelopes.
- **Database schemas:** lifecycle and authority contracts, not merely ORM models.

## G0 contract decisions accepted; runtime exit criteria remain open

The following contract shapes and safety semantics were accepted by Rick1330 (acting owner across all roles) on 2026-10-10. No independent reviewer is named in the decision record. Review/expiry is 2026-11-10, or earlier on material change. This acceptance authorizes no runtime implementation, production profile, hosted/HA claim, or G1–G4 exit. Runtime seams remain provisional.

- **Principal and agent binding:** AuthService-issued `PrincipalContext` is authoritative; caller selectors never establish tenant/agent authority. Token-agent mismatch denies before lookup. The accepted first seam is additive and does not imply repo-wide propagation. Source: `21-g0-owner-decision-record.md:15-17` and the current auth/proxy anchors below.
- **PolicySnapshot authority and freshness:** AuthService's policy-signing key set is authoritative. The immutable snapshot carries authority, key ID, snapshot ID, digest, effective epoch, issued time, and expiry; unknown/revoked/expired keys fail closed. Accepted maximum ages are 60 seconds for protected reads/context assembly, 30 seconds for mutation/external effects, and five minutes from durable claim for asynchronous continuation, with five seconds bounded clock skew. These are local/protected contract defaults, not runtime or hosted evidence. Source: `21-g0-owner-decision-record.md:28-44`.
- **RunEnvelope lineage:** server-minted run/attempt identities and parent/fork/operation/policy-snapshot linkage are correlation only, never permission. Retry/resume/fork revalidates current authority. Durable storage, replay, approval consumption, and cross-boundary propagation remain deferred. Source: `04-principal-policy-and-run.md:33-37` and `21-g0-owner-decision-record.md:80-84`.
- **Idempotency/replay/conflict:** accepted scope is `(org_id, agent_id, operation_scope, idempotency_key)` with verified org/agent and server-assigned operation scope. Same-body retries replay/reconcile; digest mismatch is typed conflict; uncertain external effects reconcile by operation ID rather than blind retry. RFC 8785 JCS (`jcs/v1`) is adopted; durable ledger, TTL, and operation-specific response mappings remain implementation work. Source: `21-g0-owner-decision-record.md:19-20` and `03-contract-registry.md:41-55`.
- **Redaction, retention, and deletion:** producer-boundary class is mandatory; absent class stays `unclassified`; relay rejects unclassified/prohibited/unsupported values. The accepted ordinary-evidence retention baseline is 30 days after `occurred_at`; legal/incident holds block deletion until authorized release. Metadata validation does not prove payload sanitization. Source: `21-g0-owner-decision-record.md:21-22,63-65`; `packages/evidenceoutbox/types.go` and `relay.go`.
- **Acknowledgement/uncertified behavior:** evidence-required success follows durable outbox commit; failure or unknown commit cannot be reported as success. Typed `uncertified` is allowed only for an explicitly degraded profile with durable reconciliation state. The repository has status/mapping helpers, but the deferred session producer remains post-response and does not establish a synchronous response acknowledgement. Source: `21-g0-owner-decision-record.md:20-21`; `services/proxy/internal/http/session/evidence.go` and `evidence_ack.go`.
- **Relay/sink dedupe and tombstone fence:** ClickHouse is selected as the v1 projection target, but its adapter remains G4-gated. The resource-owning service owns lifecycle records; PostgreSQL provides the authoritative org-scoped fence, checked atomically with projection or fail-closed. Delivery is at-least-once and dedupes `(org_id, event_id, aggregate_seq)`; no sink infers deletion from event content or aggregate ID. Source: `21-g0-owner-decision-record.md:21-22,59-61`; `packages/evidenceoutbox/types.go` and `relay.go`.
- **Compatibility/migration:** use additive changes, never reuse protobuf tags, generate stubs from source, and use expand→dual-read/write→backfill→verify→contract with mixed-version tests and explicit rollback/roll-forward conditions. Current JSON metadata fields do not add SQL columns; durable ledgers and lifecycle-table/sink integration remain separate gates. Migration 000036 is a substrate, not proof of the complete contract. Source: `15-runtime-operations-and-recovery.md:13-19`; `infra/migrations/postgres/000036_evidence_plane.up.sql:398-429`.

## Compatibility rules

- Protobuf field numbers and names are never reused; removed fields are reserved.
- REST remains `/v1` until a deliberate major version; additive changes require examples and compatibility tests.
- MCP tool IDs, schemas, and result shapes are versioned and hashable.
- Provider aliases resolve to immutable deployment IDs before execution.
- Breaking changes require an ADR, migration, rollback/roll-forward plan, mixed-version tests, and docs.

CI must run Buf format/lint/generate/breaking checks, OpenAPI validation, golden error tests, MCP conformance, and generated-artifact reproducibility.
