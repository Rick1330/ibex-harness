**Status:** `specified`; inventory must be completed before new boundary work. The initial G0 registry packet is proposed in `web/content/docs/adr/0084-g0-principal-agent-binding-and-idempotency.mdx:10,24-34,141`; closed issue #935 is historical context, while open issue #944 and PR #943 track the current follow-up; no G0 exit is claimed.

## Contract hierarchy

- **Protobuf/gRPC:** internal multi-consumer service contracts.
- **OpenAPI/REST:** external management and resource APIs under `/v1`.
- **Provider contracts:** separately versioned Chat Completions and Responses subsets plus native adapter semantics.
- **MCP schemas:** versioned tools/resources with explicit scopes and limits.
- **Events:** durable evidence and operation envelopes.
- **Database schemas:** lifecycle and authority contracts, not merely ORM models.

## G0 exit-criteria resolutions proposed (not accepted)

The following decisions were recorded on 2026-10-08. They authorize only the bounded draft hardening in this branch; G0 remains proposed, and no new authority boundary or G0 acceptance is authorized. Role-level owners are Auth/Proxy, Context, Architecture/Proxy, Platform/Data, Evidence/Platform, Security/Privacy, and Evidence/Operations. Rick1330 is the provisional acting individual for these roles pending confirmation at the G0 owner review window, which closes 2026-10-22 (14 days after packet publication).

- **PrincipalContext requiredness and transport trust:** require `org_id`, subject ID/type, auth source, policy epoch, trace/request IDs, and absolute deadline on protected paths; require agent/project/repository/session/resource selectors and idempotency/operation fields only where that operation uses them. AuthService/enforcement derives authority; caller values are selectors only. Fail before downstream work on missing/malformed/stale/forged/cross-org/inactive/token-agent-mismatched state. First mapping is one additive proxy→context seam, not repo-wide propagation. Source: `web/engineering/architecture-v2/04-principal-policy-and-run.md:7-25,39-53`; current auth proto and middleware anchors listed below.
- **PolicySnapshot authority/epoch:** recommend the auth/enforcement plane, with AuthService issuing immutable snapshots containing ID, digest, effective epoch, and freshness window. A cache or model/output cannot widen policy. **Requires owner decision:** confirm the authority identity, numeric freshness window, allowed stale behavior, and exact degraded status. Source: `web/engineering/architecture-v2/04-principal-policy-and-run.md:27-31`.
- **RunEnvelope lineage:** server-minted logical run ID, distinct attempt ID for each attempt/retry, explicit parent/fork relation, operation ID, and policy-snapshot linkage; correlation only, never permission. Resume/retry/fork revalidates principal, policy epoch, resource and approval expiry. Durable storage, replay, approval consumption, deadline state machine, and cross-boundary propagation remain deferred. Source: `web/engineering/architecture-v2/04-principal-policy-and-run.md:33-37`.
- **Idempotency/replay/conflict:** freeze the tenant/resource-operation key tuple `(org_id, operation_scope, idempotency_key)`; same-body retries return/reconcile the prior operation; a changed body returns stable typed conflict with no second effect; ambiguous completion reconciles by operation ID; retry only after a durable claim. Adopt SHA-256 over versioned RFC 8785 JCS canonical UTF-8 JSON (`jcs/v1`). Go and Python conformance vectors must cover duplicate keys, Unicode, numeric-domain limits, and absent/default fields. Durable PostgreSQL table/operation scope, TTL, and service-specific status mappings still require owner approval; Redis may cache but must not be authority. Source: `web/engineering/architecture-v2/03-contract-registry.md:41-55`.
- **Redaction:** producers classify only after sanitization. The Go envelope carries `unclassified`, `metadata`, or `prohibited`; absent classification remains `unclassified`, and the relay rejects unclassified, prohibited, and unsupported classes before delivery. Credentials, tokens, prompts, memory bodies, embeddings, and unredacted PII remain prohibited from ordinary event/log payloads; sensitive artifacts require approved access-controlled references. Retention/legal-hold/deletion semantics remain open. Source: `web/engineering/architecture-v2/10-evidence-contract.md:5-19`; `packages/evidenceoutbox/types.go` and `packages/evidenceoutbox/relay.go`.
- **Acknowledgement/uncertified behavior:** durable-before-ack is the default for evidence-required profiles. A typed, machine-readable `uncertified` outcome is permitted only when the selected sink and redaction contract explicitly allow degraded operation; silent log-and-continue is forbidden. The existing detached logging call is not compliant and remains an open implementation gap. Source: `web/content/docs/adr/0084-g0-principal-agent-binding-and-idempotency.mdx:79-87`; `services/proxy/internal/http/session/evidence.go:16-64`.
- **Relay/sink dedupe and tombstone fence:** select ClickHouse as the v1 sink; its adapter remains G4-gated and is not built in this round. The PostgreSQL resource-lifecycle table, owned by Platform/Data, is the canonical tombstone/version authority. A sink must atomically check the org-scoped fence with the projection write, fail closed if unavailable, and dedupe `(event_id, aggregate_seq)` with an `org_id` predicate. The Go payload carries the optional fence key and relay requires the fence-aware delivery hook; no fence is inferred from `aggregate_id` or event contents. Source: `web/engineering/architecture-v2/10-evidence-contract.md:9-19`; `packages/evidenceoutbox/types.go`; `packages/evidenceoutbox/relay.go`.
- **Compatibility/migration:** v1 changes are additive; never reuse protobuf tags; generate stubs from source; use expand→dual-read/write→backfill→verify→contract, mixed-version tests, lock/timeouts and explicit roll-forward/rollback triggers. The approved redaction-class and fence fields are additive Go/JSON envelope fields and require no database migration in this round. Durable run/operation changes and the lifecycle-table/sink integration remain separately gated. Evidence schema v1 and migration 000036 are current substrates, not proof of the full G0 contract. Source: `web/engineering/architecture-v2/03-contract-registry.md:139-147`; `web/engineering/architecture-v2/15-runtime-operations-and-recovery.md:13-19`; `infra/migrations/postgres/000036_evidence_plane.up.sql:398-429`.

- Breaking changes require an ADR, migration, rollback/roll-forward plan, mixed-version tests, and docs.
