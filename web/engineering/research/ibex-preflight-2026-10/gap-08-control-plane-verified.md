## 1. Strategy intent versus verified state

The strategy defines a control plane that keeps model-visible text, skills, rules, memory, tool descriptions, and tool results as untrusted context; authority must come from verified principal, policy/capability admission, approvals, sandbox admission, and a governed executor (`IBEX Harness_ Product Strategy, Gap Audit, and Recommended Redesign.md#L885-L897`). It calls for: immutable tenant-scoped skill versions and descriptors; exact versioned/hash-bound tool descriptors and calls; approvals bound to exact canonical action bytes, resource, policy/version, expiry, reviewer, and idempotency; isolated execution with deny-by-default egress and brokered secrets; durable runs/workspaces/artifacts; and a signed `DeploymentSnapshot` as the unit of promotion/execution with a derived `RunManifest` (`...md#L899-L920`, `#L941-L965`, `#L983-L1003`).

The canonical repository documents deliberately treat this as target design rather than shipped behavior. `web/engineering/architecture-v2/02-plane-boundaries.md#L15-L23` assigns tool execution to a governed executor and operator actions to the management API; `17-roadmap-and-gates.md#L7-L18` places control-plane side effects in G9 and requires G0–G8 first. `00-status-and-evidence.md#L29-L35` says the G0 packet is proposed, not accepted, and explicitly blocks control-plane effects. The implementation plan also defers the broad skills/approvals/execution/composite-deployment plane (`ibex-harness-implementation-plan.md#L13-L15`, `#L170-L177`).

## 2. Verified current implementation

### 2.1 What is real, but narrow

* **Tenant-scoped directive/version precedent:** `infra/migrations/postgres/000009_create_directives.up.sql#L9-L50` stores org-scoped directives and append-only directive versions with content hashes; `#L120-L150` applies RLS and rejects version updates. This is a directive history, not a composite deployment snapshot, skill registry, policy bundle, or execution manifest.
* **Evidence fragments:** `000036_evidence_plane.up.sql#L122-L164` creates request/trace-level `evidence_runs`; `#L334-L360` creates `evidence_directive_snapshots`; `#L362-L393` creates org-RLS `evidence_tool_audits` containing `tool_name`, `idempotency_key`, sanitized args, and status. These are evidence records only: they do not authorize or dispatch tools. `000039_evidence_deploy_digest.up.sql#L1-L7` stores only the OCI **service build** digest, not a complete deployment snapshot.
* **Operator metadata reads:** `services/api/app/routers/operator_traces.py#L28-L120` mounts only `GET /v1/operator/traces`, `/runs/{run_id}`, and `/{trace_id}`. The unit suite tests metadata/publication/detail behavior (`services/api/tests/unit/test_operator_traces.py::test_list_is_metadata_only_and_binds_org_and_query`, `::test_run_detail_hydrates_child_sections_and_interim_score_note`); the integration test `services/api/tests/integration/test_operator_traces_rls.py::test_operator_traces_are_tenant_scoped_with_publication_and_404_boundary` verifies Org A/B RLS and 404 anti-enumeration. This is read-only operator visibility, not action control.
* **Operator ledger hooks:** `services/api/app/services/operator_ledger.py#L23-L28` trims and rejects an empty preview token but explicitly says the issuer “lands later”; `#L56-L69` only rejects a missing or same-ID second actor. `services/api/app/repositories/operator_ledger.py#L11-L53` inserts a row. The migration `000035_operator_action_ledger.up.sql#L3-L35` has org, actor, action/resource, preview token, optional step-up JTI, second-actor fields, and org-scoped idempotency, with RLS. It has no approval request/grant state, canonical action/body hash, policy epoch, snapshot binding, expiry, revocation, one-time consumption, or authenticated approver proof. `services/api/tests/unit/test_operator_ledger.py#L14-L125` tests only hook behavior and SQL parameter passing; it is not an end-to-end approval test.
* **Session/checkpoint substrate:** `packages/session/store.go#L12-L21` exposes tenant-aware session/checkpoint/complete/abandon operations, and `packages/session/store_unit_test.go::TestUnit_AppendCheckpoint_RejectsNegativeStats` plus the package tests cover local checkpoint validation. This is not a durable general run executor: no approval revalidation, operation intent/receipt, leases/fencing, workspace, egress, credential, reconciliation, or side-effect lifecycle is present.
* **Evidence relay hardening:** `packages/evidenceoutbox/README.md#L7-L11` accurately states this is a shared package, not a deployable process and not hosted-production evidence. `000036_evidence_plane.up.sql#L398-L438` provides an org-RLS transactional outbox and `#L445-L587` least-privilege claim/recover/mark helpers. #936 added payload integrity/replay checks; current `packages/evidenceoutbox/relay.go` and tests cover malformed rows/digests and ack-loss replay. `go test ./packages/evidenceoutbox/...` passed at this ref. This improves evidence integrity but does not provide control-plane authority, an executor, or a live sink acceptance profile.

## 5. Residual subgaps and dependencies/shared ownership

1. **G0 contract/authority freeze:** Architecture/ADR owners must accept feature-specific `SkillDescriptor`, `ToolDescriptor`, `ApprovalRequest`/`ApprovalGrant`, `ExecutionPolicy`, `OperationIntent`/`OperationReceipt`, `DeploymentSnapshot`, `RunManifest`, artifact, event, and trust-label contracts. G0 is currently proposed/pending owner review.
2. **Principal/policy/run seam (G1):** Auth/Proxy + Context must establish verified `PrincipalContext`, policy epoch, resource scope, and run lineage before control-plane effects. #934 fixes one proxy agent-binding seam but does not propagate the contract across workers/MCP/evidence.
3. **Idempotency/replay and evidence (G2/G4):** Platform/Data + Evidence/Security + Operations own canonical body hashing, intent/receipt state, required-before-ack semantics, redaction, relay/sink dedupe, tombstone fencing, and recovery. Existing evidence relay package is shared code, not a running deployable process (`packages/evidenceoutbox/README.md#L5-L11`).
4. **Execution boundary (G9):** Security/Platform/Runtime must own the isolated executor, host-enforced egress, credential broker, workspace/artifact policy, resource limits, cleanup, and external-effect reconciliation. This boundary must not be placed in proxy/AuthService/MCP/Postgres/Redis/ClickHouse/MinIO.
5. **Deployment/promotion/recovery (G8→G9):** Release/Platform/SRE must name a profile, signing/attestation authority, key rotation, staged rollout/abort/rollback ownership, restore evidence, and measured RPO/RTO. Service image digest provenance cannot substitute for a composite snapshot.
6. **Operator surface:** API/Console may be clients only. `4.d.5` requires every controlled mutation to pass the backend command pipeline; fixtures, UI permission checks, and direct ledger insertion cannot authorize mutations.

## 7. Risks and uncertainties

* **Highest risk:** treating the operator ledger, preview token, UI fixtures, evidence tool-audit row, service image digest, or session checkpoint as authority. None is a control-plane authorization or immutable composite snapshot.
* **Boundary risk:** no repository-visible implementation proves whether an external deployment supplies missing control-plane services. This audit is bounded to the clean repository and canonical docs at `7298e5e`.
* **Availability/security tradeoff:** current proxy evidence persistence is optional and fail-open after response (`services/proxy/internal/http/session/evidence.go#L16-L64`); G0 must decide which events are required before acknowledgement versus best effort.
* **Test execution caveat:** read-only `go test ./packages/evidenceoutbox/...` and `go test ./packages/session/...` passed at the target ref. Python API/MCP tests were source-inspected; system Python has no `pytest` module. No production/hosted/HA environment was inspected.
* **Documentation authority:** strategy and historical research are intent/context. `web/engineering/architecture-v2/` is canonical, and it explicitly says G0 is not exited. Historical mentions under `web/engineering/research/` must not be used as implementation evidence.

## Bottom line

**GAP-08 remains open.** The current main commit has partial foundations for tenant-scoped evidence, directive versioning, operator metadata reads, narrow preview/dual-approval hooks, sessions/checkpoints, and fail-closed boundary hardening. It has **no verified skill supply chain, approval lifecycle bound to exact effects, governed executor, immutable composite deployment snapshot, promotion/rollback controller, or end-to-end control-plane acceptance evidence**. Treat the merged PRs as safety hardening and governance preparation—not as GAP-08 closure.
