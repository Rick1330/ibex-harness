## Executive finding

**Overall classification: PARTIAL / provisional; not resolved and not `shipped-accepted`.** The repository contains a functioning, narrow, tenant-aware MCP memory resource server with Streamable HTTP, bearer-token validation through AuthService, three memory tools, strict Pydantic/FastMCP argument schemas, agent verification, protected-profile Redis configuration/fail-closed error handling, and metadata-only asynchronous audit emission. These are verified local behaviors.

The target governance contract is broader: a canonical versioned/hashable tool registry, explicit per-tool policy and resource scope, immutable policy/evidence IDs, bounded input and output, whole-call deadline/cancellation, replay-safe writes, durable evidence, and read-only-first sequencing. Those are not fully implemented or accepted. The authoritative ledger still says MCP memory tools are `provisional` and that logging-only audit is not evidence-grade (`web/engineering/architecture-v2/00-status-and-evidence.md:15-35`). The current server exposes **`write_memory` and `record_feedback` before G9 governed-side-effect acceptance**, while G7 is specified as read-only-first (`web/engineering/architecture-v2/17-roadmap-and-gates.md:13-16`). There is no verified canonical descriptor/policy authority, durable MCP outbox, approval/operation receipt flow, output byte cap, absolute call deadline, or cancellation contract.

The local `mcp-governance` memo maps most closely to canonical **GAP-009** (P1) rather than a canonical GAP-06 ID. The canonical register says GAP-009 is still open: protected limiter hardening is partial and “audit/operator gap remains open” (`web/engineering/architecture-v2/18-gap-register.md:15,22-30`). The implementation plan explicitly defers MCP governance expansion until G1/G2/G4/G6 and says existing writes must be constrained by an approved profile rather than silently treated as governed (`ibex-harness-implementation-plan.md:13-15,94-105`).

## Authority and claimed-intent baseline

The architecture-v2 target says MCP is an external resource/tool boundary that must derive scope from the authenticated principal, use versioned tool descriptors and hashes, cap input/output, validate arguments, support deadlines/cancellation, require idempotency for writes, record policy/evidence IDs, and treat descriptions/results as untrusted data (`web/engineering/architecture-v2/11-operator-and-mcp-surfaces.md:13-17`). The registry requires contract ID/owner, source/generated artifacts, version/compatibility, auth/resource scope, profile, errors/retry, idempotency/deadline/cancellation, tests/evidence, and support window (`03-contract-registry.md:14-26,41-57,69-77`).

Those are **specified targets**, not a declaration that the runtime has them. The status ledger explicitly requires source+commit, test/benchmark/recovery/hosted artifact, profile/dependencies, owner/date, limitations, and review/expiry before `shipped-accepted`; it also says MCP remains `provisional` (`00-status-and-evidence.md:5-35`). A PR merge is not an acceptance artifact (`00-status-and-evidence.md:31-35`).

ADR-0050 is narrower historical intent: an accepted resource-server skeleton with Streamable HTTP, AuthService validation, two initial tools, metadata-only async ClickHouse audit, and local-only stdio. It expressly says it is not an OAuth authorization server and that later feedback/lineage tools are later milestones (`web/content/docs/adr/0050-mcp-server-skeleton.mdx:23-26,31-56,58-63`). Current code has expanded beyond that ADR to a real memory client and `record_feedback`; that expansion is verified implementation, but it does not prove acceptance of the wider governance contract.

2. **Policy authority:** define per-tool permissions, role/purpose/classification, resource selectors, immutable policy snapshot/epoch, stale-policy denial, and policy decision ID; emit these IDs with every allow/deny.
3. **Side-effect disposition:** explicitly disable/hide `write_memory` and `record_feedback` on profiles claiming G7 read-only, or document a narrow backward-compatible local/provisional exception. Do not generalize the current handlers into an arbitrary executor.
4. **Write replay:** bind idempotency to all semantically relevant inputs (`category`, `confidence`, feedback target/body and versioned canonical payload), durable operation ID/state, same-key/same-body replay, changed-body conflict, ambiguous timeout reconciliation, concurrent retries, TTL/expiry, and no duplicate authoritative effect.
5. **Approval/receipt/G9:** for any production mutation, add exact descriptor binding, operation intent, approval reference where required, receipt, reconciliation state, egress/credential/isolation policy, and evidence. This is later G9 scope, not a small change to the current unit key.
6. **Evidence:** route MCP events to the canonical durable evidence/outbox authority; include org/subject/agent, request/run/operation/event IDs, descriptor digest, policy snapshot/epoch, decision, approval, status/error, timing, redaction class, and safe payload digest. 7. **Evidence failure tests:** crash, queue saturation, sink outage, duplicate/replay, shutdown drain, ack loss, retention, restore, poison handling, tenant/RLS, and reconciliation. Do not call ClickHouse/log output evidence-grade by itself.

12. **Interoperability:** run official MCP conformance tooling, supported real-client fixtures for each claimed protocol/transport, pinned versions and auth/configuration limitations, and record deployment-profile acceptance.

## Dependencies and shared-boundary ownership

- **G0 / Architecture + Auth/Policy + Evidence/Security + Deployment:** freeze descriptor/version/hash format, principal/policy authority, trust labels, profiles, write disposition, failure semantics, evidence acknowledgement, migration/rollback, and owners before new boundary/side-effect work. `17-roadmap-and-gates.md:26-30` makes this a hard gate.
- **G1 principal/tenant:** AuthService/enforcement owns verified org/subject/agent/resource scope and anti-enumeration. MCP consumes it; it must not derive authority from caller selectors, tool descriptions, memory text, or headers. Current AuthService/agent-verifier slices are helpful but do not provide MCP policy snapshots.
- **G2 idempotency/replay:** Platform/Data owns canonical operation identity, body hashes, conflict and uncertain-commit semantics. MCP writes depend on it; the current content-only key is not a shared operation contract.
- **G4 evidence:** Evidence/Platform owns PostgreSQL/outbox authority, stable event identity, redaction, acknowledgement class, relay/sink dedupe, and restore. MCP `AsyncAuditEmitter` is only a local adapter/projection and must not become a second authority.
- **G6 memory/context:** Memory + Context owns typed memory authorization, per-object ownership, tombstone/validity/provenance, feedback target checks, output filtering, and safe degradation. MCP cannot prove `record_feedback` object authorization from its current code.
- **G7 MCP/operator:** MCP + Security owns read-only descriptors, output/deadline/cancel limits, policy binding, conformance, protected limiter profile, and stdio policy. Operator/Management API owns operator approvals/diagnostics; MCP should not create an ad hoc approval authority.
- **G8 operations/recovery:** Platform/SRE owns named deployment profiles, Redis/ClickHouse/Postgres availability, drain, backup/restore, retention, RPO/RTO, and readiness. Current `/ready` checks AuthService only (`main.py:219-233`).
- **G9 governed side effects:** Security/Operations/Platform owns approval, exact action descriptor, egress, credentials, isolated execution, operation receipt and reconciliation. Existing memory writes should remain separately profiled until this gate.
- **External OAuth/IdP boundary:** ADR-0050 and README make MCP a resource server. IdP registration, OAuth authorization-server behavior, client provisioning, token issuance and deployment identity mapping remain external/deployment responsibilities, not missing MCP server code. That boundary must be documented in any interoperability acceptance claim.

## Exact acceptance checks required before any “resolved” or `shipped-accepted` claim

1. **Clean provenance:** reproduce from a clean checkout at the exact source commit; record test/evidence artifact, profile, dependencies, owner, verification date, limitations, and review/expiry in `00-status-and-evidence.md`.
2. **Registry integrity:** canonical registry contains all three tools (or explicitly approved read-only subset) with stable ID/version/compatibility, source/owner, auth/resource scope, profile, schema/result limits, deadline/cancel, retry/error/idempotency, trust label, and SHA-256 descriptor digest. CI proves generated FastMCP schema parity and denies registry/schema mismatch or unavailable registry.
3. **Principal/policy negatives:** test missing/stale/mismatched principal, token-agent mismatch, cross-org agent/resource, same-org policy boundary, suspended agent, stale policy epoch, anti-enumeration, and missing policy. Each denial must make zero memory/backend calls and emit a policy/evidence-linked denial.
4. **Authorization matrix:** test search, write, feedback across org/user/agent/resource combinations, including cross-org and forged `memory_id` feedback. Backend ownership and MCP prechecks must have an explicit owner and evidence.
5. **Limits/cancel:** test min/max/unknown arguments, request byte limit, per-result and aggregate response bytes, slow backend/dependency timeout, absolute deadline budget, client cancellation/disconnect, and cleanup/no work after cancellation.
6. **Write replay:** test same key + same canonical full payload returns one result/effect; same key + changed payload gives stable conflict; timeout after backend commit reconciles by operation ID; concurrent duplicates, TTL expiry, feedback replay, tenant isolation, and no retry after client-visible partial output.
7. **Rate-limit profile:** staging/production tests for Redis unset, connection failure, command timeout, failover/recovery, multi-replica key consistency, over-limit, readiness, and shutdown. No protected profile may silently select `NoopMcpLimiter`; `/ready` must not claim healthy when required limiter integrity is unavailable.
8. **Durable evidence:** crash/queue saturation/sink outage/ack loss/duplicate/replay/poison/shutdown drain/retention/restore tests. Verify required-before-ack or durable `uncertified` response semantics, sink dedupe, tenant filtering, redaction, sequence continuity, and reconciliation. Logging/ClickHouse-only success is insufficient.
9. **Untrusted data:** inject prompt-injection text, secrets, PII and oversized results; verify caps, redaction/trust labels, no authority escalation, and no unsafe ordinary logs/evidence.
10. **Read-only profile/G9 boundary:** tools/list and tools/call on a G7 profile expose only accepted read-only tools. If writes remain enabled for compatibility, document profile, permissions, risk owner, and explicit provisional status; for G9 acceptance require descriptor-bound intent/approval/receipt/egress/isolation/reconciliation.
11. **Interop:** run official conformance plus supported client fixtures for every claimed protocol/transport; pin versions, auth/discovery expectations, retries, limitations, and hosted/deployment evidence. Keep stdio local-only unless a named profile/risk review proves identity propagation and evidence.
12. **Readiness/recovery:** prove required dependencies and contracts in `/ready`, graceful cancellation/drain, restore and retention behavior, named RPO/RTO, and operator diagnostics without secrets/cross-tenant existence.

## Risks and uncertainties

- **Evidence loss is demonstrated, not hypothetical:** `test_audit.py:test_queue_full_drops` proves queue overflow drops events; `_run` logs sink errors and continues. A tool call can succeed without durable evidence.
- **Protected rate limiting is profile-dependent:** PR #936 fixes normal staging/production construction but leaves development/no-Redis permissive and direct dependency injection permissive. Deployment/bootstrap facts outside the repository are unknown.
- **Feedback object authorization is delegated:** this service sends `memory_id` to the memory API. Repository-local tests do not prove cross-org/forged feedback IDs are denied by the backend.
