# GAP-07 evidence and recovery — verified audit

**Audit target:** `Rick1330/ibex-harness`, clean `main` at `7298e5ee7982b926630566c88830c99650c8eb37` (`7298e5e`, PR #937 merge).

**Scope:** Durable evidence and recovery only. Read-only inspection of the assigned gap memo, product strategy, implementation plan, 2026-10-06 session report, current source/tests/docs, and merged PRs #934, #936, and #937. No repository source, configuration, or documentation files were changed. The only created artifact is this report.

**Bottom line:** **GAP-07 remains partial/open overall.** The checkout verifies useful local foundations—PostgreSQL evidence tables with tenant RLS, an atomic `PersistRun` transaction, an at-least-once relay library with lease/retry/poison helpers, payload-integrity validation, and a real local Postgres dump/restore drill. It does **not** verify a durable evidence-grade product guarantee: the proxy writer is optional, deferred until after the response, and fail-open; no non-test runtime caller or concrete sink for `Relay` is present; stable write retry identity and true crash-after-sink-before-ack behavior are not proven; arbitrary evidence input is not redacted by the shared writer; the committed recovery artifact explicitly has no measured Postgres RPO/PITR and no ClickHouse/MinIO recovery; and the outbox RPO check is vacuous/too weak for sequence continuity and sink reconciliation. No G0/G4/G8 acceptance record promotes this to `shipped-accepted`.

## 1. Authority and strategy intent

The product strategy defines IBEX as a self-hostable, multi-tenant agent control/context plane whose differentiator includes **durable evidence** (strategy, “Evidence plane,” lines 73–79). The evidence plane is intended to record admission, identity, policy, reservations, provider attempts/usage, context decisions, tools, approvals, retries, fallbacks, errors, and artifacts; asynchronous logging must not be called evidence-grade audit until durable delivery, replay, deduplication, retention, and restore are real.

The canonical repository contract is stricter than local code presence:

- `web/engineering/architecture-v2/10-evidence-contract.md:3` says the contract is `specified` and existing outbox coverage is **partial** until the status ledger proves otherwise.
- `10-evidence-contract.md:7-19` requires a complete envelope, atomic canonical-state/outbox writes for required-before-ack events, at-least-once relay, consumer dedupe, tombstone replay fencing, canonical authority, minimum event classes, and privacy minimization.
- `web/engineering/architecture-v2/00-status-and-evidence.md:7-13` requires source/commit, test or recovery artifact, profile/dependencies, owner/date, limitations, and review date before `shipped-accepted`.
- `00-status-and-evidence.md:31-35,42` explicitly calls the G0 packet proposed, labels the relay slice `provisional`, and says its tests do not establish evidence acknowledgement timing, sink deployment, tombstone fencing, hosted recovery, or exactly-once effects outside the test sink.
- The recovery milestone remains `in-progress / partial`: `web/content/roadmap/phase-4-multi-provider/milestones/4.p.5-production-platform-recovery-supply-chain.mdx:18-26,35-41,51-58` requires real PITR, measured RPO/RTO, object/ClickHouse policy, and environment-specific artifacts.

The supplied GAP-07 memo is therefore directionally correct: local components justify bounded `shipped-local`, not an overall `shipped-accepted` claim.

## 5. Residual subgaps

1. **Acknowledgement contract:** decide which event classes are required-before-ack versus explicitly best-effort; make required writes transactional with response certification or return a machine-readable `uncertified/unavailable` outcome. Queue-full, disabled writer, DB failure, cancellation, and shutdown loss must be attributable and repairable.
2. **Stable evidence operation identity:** add event/request idempotency key and lookup-return-existing behavior for uncertain commit/retry. Preserve one canonical run and avoid uniqueness-error ambiguity.
3. **Runtime relay ownership:** choose an already accepted worker/runtime profile or record a new ADR; instantiate the relay, configure lifecycle/lease recovery/drain, and expose pending age/attempt/failed/poison/watermark metrics.
4. **Concrete sink and dedupe:** implement one tenant-preserving sink with stable event-ID plus aggregate-sequence/version dedupe, schema compatibility, replay handling, and durable checkpoint/watermark semantics.
5. **Crash matrix:** process kill after claim, after sink apply before ack, during ack, relay restart, duplicate/reordered/missing/poison event, sink outage, shutdown drain, and consumer-version skew.
6. **Redaction/privacy:** sanitize or reject arbitrary span attributes, session-event data, score components, tool args, error fields, and artifact references; add secret/raw-prompt/PII tests and retention/legal-hold classifications.
7. **Event coverage:** instrument admission/deny, budgets/reservations/reconciliation, provider attempts/usage, context manifest, memory operations/deletion, MCP/tool, approvals, model decisions, artifacts, and operator actions.
8. **Tombstone/replay fencing:** make authoritative deletion/tombstone checks part of sink application or require a version/deletion fence; prove no replay resurrection after deletion, cache rebuild, restore, or projection rebuild.
9. **Recovery proof:** provide named profile inventory and real pgBackRest/WAL/PITR restore with recoverable keys, measured RPO/RTO, schema/config/image digests, migration/rollback evidence, and service usability after restore.
10. **Outbox continuity math:** count every nonterminal state; verify per-aggregate sequence coverage from a nonempty fixture; reconcile canonical state, retained outbox, sink-applied state, tombstones, and watermarks; fail explicitly on empty/vacuous datasets.
11. **Multi-store recovery:** restore/rebuild ClickHouse projection and encrypted MinIO/object metadata/artifacts (or document an accepted alternate policy); verify tenant negatives, deletion/holds, and replay fencing across stores. Keep Redis cache-only only under an explicit accepted contract.
12. **Acceptance governance:** record G0/G4/G8 owner decisions with profile, commit/config/dependency digests, artifact links, limitations, verification date, and expiry/review date. Do not close GAP-07 by prose or merge status.

## 6. Dependencies and shared-boundary ownership

- **Architecture/contract/G0 owners:** freeze event envelope, required-before-ack policy, canonical authority per data class, idempotency key, replay/tombstone/retention/legal-hold semantics, and profile boundaries before new side-effect or service boundaries.
- **Proxy/enforcement owner:** decide how evidence status appears in the client contract; own synchronous/async capture choice, queue saturation, request certification, and loss/uncertified signaling. The current boundary is `services/proxy/internal/http/session/{evidence.go,snapshot.go}`.
- **Evidence package/schema owner:** own `PersistRun`, stable event identity, payload redaction/classification, schema constraints, migration compatibility, and outbox state/checkpoint/watermark semantics (`packages/evidenceoutbox/*`, `000036_evidence_plane.up.sql`).
- **Relay/platform owner:** own runtime instantiation, least-privilege `ibex_evidence_relay` credentials, process lifecycle, retries, stale-lease recovery, drain, metrics/alerts, and deployment profile. Current SQL helpers are intentionally a privileged cross-tenant boundary; do not grant them to `ibex_app`.
- **Sink/analytics owner:** own concrete ClickHouse/object sink, event schema/version handling, tenant predicates, dedupe, ordering/gap policy, tombstone fencing, and projection rebuild/reconciliation. ClickHouse/OTel remain projections, not sole authority.
- **Privacy/security/legal owner:** own no-prompt/no-completion boundary, arbitrary metadata/tool-arg sanitizer, encryption/key recovery, retention/legal holds, export/deletion receipts, and cross-tenant non-enumeration.
- **SRE/backup/recovery owner:** own pgBackRest/WAL archive freshness, PITR, keys/secrets, backup retention, clean-cluster drills, measured RPO/RTO, migration/rollback, and named single-node/HA/staging profiles.
- **Memory/deletion owner:** own authoritative tombstones and deletion fanout; relay/sinks must consume the fence so evidence replay cannot resurrect deleted lifecycle state.
- **Operator/read API owner:** expose `partial`, `unavailable`, or `uncertified` rather than empty-success when publication or store recovery is absent; link status to canonical evidence ledger. ADR-0083’s narrow metadata/read slice does not certify publication/recovery.

## 7. Exact acceptance checks required before GAP-07 closure

1. **G0 record:** dated owner decision names event classes, profile, authority, idempotency, acknowledgement, redaction, retention/hold, tombstone, replay, migration/rollback, and recovery semantics; ledger links exact commit/config/dependency digests and expiry/review date.
2. **Required-write behavior:** inject DB failure, commit ambiguity, disabled writer, queue saturation, process shutdown, and relay outage; assert required-before-ack requests do not return certified success. Best-effort events must return machine-readable `uncertified`/loss status and emit repair/alert metrics.
3. **Stable retry:** submit same tenant/request/event key with same body before and after an uncertain commit; assert one canonical run/event and same operation/result. Change body under same key; assert stable conflict and zero duplicate writes.
4. **Atomicity:** in a live PostgreSQL profile, force each child/outbox insert and commit failure; assert no partial canonical/outbox graph. Verify RLS with non-superuser roles and cross-tenant negative queries.
5. **Relay runtime:** start the configured service/worker from the named deployment profile; repeatedly claim, deliver, recover stale leases, drain on shutdown, and restart. Assert pending age, attempts, failed, poison, and watermark metrics/alerts.
6. **Sink dedupe/crash:** kill between sink apply and DB ack and restart; assert delivery may be attempted again but sink effect count remains one by stable event identity + aggregate sequence/version. Test duplicate, reorder, gap, poison, delayed, sink outage, and consumer-version cases.
7. **Tombstone fence:** delete/hold a resource, then replay pre-delete and in-flight events after worker restart/restore/projection rebuild; assert no resurrection and correct suppression/receipt semantics.
8. **Privacy:** feed arbitrary sensitive keys, raw prompt/completion, bearer/token/secret-like values, PII, and oversized/error payloads through every `SpanInput.Attributes`, `SessionEventInput.Data`, `ToolAudit.SanitizedArgs`, and artifact path; assert rejection or deterministic redaction and no sensitive sink/log/backup output.
9. **Event completeness:** for each minimum class in `10-evidence-contract.md:13-15`, run allow/deny/degraded/retry/fallback/delete/approval scenarios; assert required event exists, links principal/resource/run/policy/degradation, and is queryable with tenant scope.
10. **Non-vacuous outbox continuity:** restore a nonempty fixture with multiple aggregates and sequences; count `pending`, `in_flight`, `failed`, `poison`, and `delivered`; fail on any unresolved nonterminal state, missing sequence, sink/canonical mismatch, unreadable checkpoint, or empty fixture; verify deletion fences.
11. **Postgres recovery:** execute real pgBackRest/WAL/PITR on a clean dedicated environment; measure actual RPO from recoverable WAL point and RTO from restore-to-usable-service; include key/secret recovery, schema/config/image digests, migrations, rollback, tenant-negative and deletion checks.
12. **ClickHouse/MinIO/object recovery:** restore or rebuild each configured evidence projection/artifact class, measure per-store RPO/RTO, verify encryption/key access, tenant filtering, retention/holds, deletion receipts, and replay reconciliation. Explicitly document Redis as rebuildable cache if retained.
13. **Profile promotion:** repeat for every claimed profile (local, staging, HA/production as applicable), attach reproducible artifacts, and promote only the bounded profile capability. A green unit test or merged PR alone is insufficient.

## 8. Risks and uncertainties

- The required-before-ack decision changes availability and streaming semantics; no product/owner decision is visible in the audited repository.
- Absence of a relay caller/sink is bounded to this repository and commit; an external deployment mechanism not checked in cannot be ruled out, but it cannot support a repository-verifiable acceptance claim.
- The committed report’s `evidence_eligible: true` is not equivalent to full recovery acceptance because `postgres.rpo_pass` is false, ClickHouse is unreachable/unmeasured, MinIO is unmeasured, and outbox proof is empty/vacuous.
- Integration-tagged Go tests passed in this environment’s process, but `openTestDB` skips without a live PostgreSQL DSN; they should not be represented as live DB acceptance.
- `SanitizedArgs` is a caller-facing name, not proof that content has been sanitized. The package currently trusts arbitrary maps.
- The schema’s `(org_id, request_id)` run uniqueness is useful protection but not an idempotent retry API; uncertain commit handling remains ambiguous.
- Aggregate sequence is local to one `PersistRun` aggregate and starts at one (`runWriter.seq`), so global `MAX(aggregate_seq)` cannot prove continuity across aggregates.
- `SECURITY DEFINER`/`BYPASSRLS` relay helpers are a high-consequence shared boundary. A future runtime must preserve narrow role grants, org IDs, sink tenant predicates, and operator non-enumeration.
- Redis omission from backup is intentional in the checked-in report, but this is a contract decision, not evidence that all caches are harmless in every profile.
- No status-ledger row accepts full GAP-07. Architecture docs/ADR text is useful intent and scope evidence, not an acceptance artifact.

## 9. Final classification

**Overall GAP-07: `partial` / `shipped-local` for bounded foundations; `open` for durable evidence and recovery acceptance.**

Verified local claims:

- atomic Postgres evidence/outbox transaction;
- evidence/outbox tenant RLS and narrow SQL helper grants;
- relay claim/retry/poison/recovery algorithms;
- pre-sink identity and payload-digest validation;
- deterministic test-double ack-loss replay behavior;
- real local pg_dump restore plus a two-tenant RLS check;
- honest explicit failure of Postgres RPO for the non-PITR mechanism.

Not verified and not closable from this checkout:

- required-before-ack evidence guarantee or explicit certified/uncertified response contract;
- stable evidence write retry/idempotency;
- running relay and concrete deduplicating sink;
- process-kill crash semantics and tombstone replay fencing;
- arbitrary input redaction/retention/legal-hold enforcement;
