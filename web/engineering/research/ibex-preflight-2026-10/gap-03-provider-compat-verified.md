## Executive finding

**GAP-03 remains open P1.** The repository has a useful **shipped-local** substrate—exact model-ID capability metadata, startup registry/overlay validation, OpenAI-compatible and Anthropic adapters, tokenizer wiring, organization model policy, breakers, and pre-stream error fallback—but it does not verify the architecture-v2 provider contract end to end. The target contract requires public aliases resolving to immutable deployment identities/manifests, complete feature and operational capability dimensions, request-time admission before provider I/O, separate lossless Chat and Responses contracts, safe fallback across policy/capability/budget/residency/idempotency, and named-profile acceptance evidence. Those behaviors are either absent, partial, or unproven in this checkout.

This is a distinction between **claimed intent** and **verified behavior**: ADRs and architecture documents specify the desired contract; local unit tests pass for the bounded fragments they cover, but no test or status-ledger artifact establishes broad provider compatibility, hosted/HA acceptance, or formal G0 exit.

## Strategy and plan intent

The product strategy says IBEX should be a compatible model endpoint that lets existing agents change one base URL, while differentiating with a typed Go contract, strict unsupported-feature errors, provider capability discovery, budgets, tenant identity, and evidence (`IBEX Harness_ Product Strategy, Gap Audit, and Recommended Redesign.md:9–15,113–121`). It explicitly warns that provider/framework compatibility grows across streaming, tools, structured output, reasoning, continuation, embeddings, usage, retries, and error formats (`...md:89–101`). For OpenAI Agents SDK interoperability it requires both Chat Completions and a **lossless, separate Responses-compatible path**; flattening Responses into Chat would lose continuation, tool/MCP items, response IDs, streaming order, and replay (`...md:189–202`).

The implementation plan classifies the local provider row as **adapter/catalog substrate shipped-local; GAP-008 specified/open P1**, with no immutable alias/deployment resolver, incomplete feature admission/usage/conformance, incomplete fallback predicate, and absent production/HA acceptance (`ibex-harness-implementation-plan.md:17–29,31–40`). It makes provider compatibility downstream of G1 identity/tenant invariants, G2 idempotency/replay, G4 evidence, and G3 budget admission (`...md:42–53`).

The supplied GAP-03 memo reaches the same conclusion: `specified` contract/open P1, local implementation partial and `shipped-local`, not `shipped-accepted` (`gap-03-provider-compat.md:8–23`).

## Dependencies and shared-boundary ownership

- **Architecture/G0/ADR owner:** freezes the contract registry, manifest schema/versioning, support-state semantics, stable errors, authority/source-of-truth, and acceptance profiles before code expansion.
- **Identity/policy (G1):** supplies verified tenant/principal/agent/resource scope and organization model policy; resolver and fallback must be tenant-bound and must not trust caller-provided alias metadata.
- **Idempotency/replay (G2):** classifies request side effects, acceptance ambiguity, retry safety, continuation, and fallback eligibility; non-idempotent/tool requests cannot be blindly retried.
- **Budget (G3):** owns authoritative pre-call estimate/reservation/settlement, pricing references, and denial/no-provider-call behavior. PR #934's failure mapping is not this ledger.
- **Provider/proxy (G3/G5):** owns adapter contracts, manifest resolver, admission gate, normalized errors/usage, stream semantics, fallback predicate implementation, and conformance fixtures.
- **Tokenizer/context (G3/G5):** owns exact versus estimated token-count quality, context/output fit, and lifecycle ordering. Architecture target is identity → policy → reservation → capability/token fit → context → provider (`05-request-lifecycle-and-slos.md:7–14`).
- **Evidence/security (G4):** owns provider-attempt/fallback/usage event identity, redaction, acknowledgement semantics, replay/dedup, and durable evidence path.
- **Platform/SRE:** owns named Compose/self-hosted/HA profiles, dependency/artifact/config digests, hosted execution, latency benchmarks, drift monitoring, rollback, and acceptance ledger evidence.
- **Control-plane/credential boundary:** owns deployment promotion/rollback and credential handles/classes; secret material must never enter manifests or evidence. Do not invent a new dynamic service boundary before G0 authority is accepted.

## Risks and uncertainties

- **High risk:** advertising a boolean capability catalog as if it were adapter-complete can silently lose tools, images, reasoning, structured output, or stream semantics.
- **High risk:** fallback without authoritative budget/residency/idempotency checks can create an unauthorized or duplicate side effect even when policy lookup succeeds.
- **High risk:** a model name is not a deployment identity; mutable aliases and stale pricing/capability metadata can route the wrong tenant or violate cost/residency rules.
- **Medium risk:** normalized OpenAI-shaped Chat output may appear compatible while losing provider-specific semantics; local happy-path tests will not expose this.
- **Medium risk:** Claude token estimates can under/over-bound context if treated as exact; hard token-fit guarantees need explicit estimate labeling and conservative failure behavior.
- **Medium risk:** current focused tests passing proves local implementation consistency only; it does not prove external-provider behavior, hosted/HA operation, or profile acceptance.
- **Uncertainty:** the audit did not find an active `/v1/responses` path or a runtime feature-admission call in scoped code, but an external/generated/unscoped deployment mechanism could exist outside this checkout. Such evidence would need to be tied to the canonical authority and acceptance ledger before changing this assessment.
- **Uncertainty:** the supplied memo was written against an earlier revision and reported `go: command not found`; at target `7298e5e`, the focused provider/tokenizer/bootstrap/proxy command passed after sourcing the pinned toolchain. This updates only test-execution status, not the missing compatibility evidence.

## Conclusion

Keep GAP-03/GAP-008 **open P1**, record the current catalog/adapters/tokenizer/fallback as **shipped-local partial slices**, and do not claim broad provider/client compatibility or `shipped-accepted`. The correct next sequence is G0 contract/authority freeze, G1/G2/G3/G4 dependency integration, one bounded immutable deployment resolver plus pre-I/O Chat subset, then conformance/fallback/evidence/profile acceptance. PR #934 improves fail-closed routing dependencies; PRs #936 and #937 do not close provider compatibility.
