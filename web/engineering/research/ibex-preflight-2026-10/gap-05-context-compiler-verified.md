## Executive finding

**Status: partial/provisional, not accepted.** The checkout contains a substantial local assembly pipeline: parallel directive/hot/cold retrieval, model capability lookup, reserved-budget calculation, deterministic score/pack, escaped nonce-delimited rendering, gRPC serving, Go proxy injection, bounded deadlines, and directive-only fail-open behavior. Those facts are verified in code and checked-in tests.

The architecture-v2 target is stronger: authenticate and scope first; retrieve exact-key session state; hard-filter authorized active projections before ranking; pack with an authoritative tokenizer; keep directives outside untrusted data; and return rendered text plus a typed `ContextEnvelope`. The current runtime has no `ContextEnvelope`/`ContextManifest`, no context-RPC authentication interceptor or verified principal/policy epoch, approximate rather than authoritative token counts, no compiler-level returned-hit tenant/lifecycle fence, no typed omission/degradation reason, no checkpoint-history read, and no profile-specific whole-pipeline acceptance artifact.

The repository itself states this limitation. `services/context/README.md:3-5` says the implementation is loopback/trusted-network only and trusts request `org_id`/`agent_id` because the gRPC server has no authentication interceptor. `web/engineering/architecture-v2/00-status-and-evidence.md:7-13,17-23` says `shipped-accepted` requires source/commit, evidence artifact, profile/dependencies, owner/date, and limitations; its baseline labels context assembly `provisional`. A PR merge is explicitly not an acceptance artifact (`00-status-and-evidence.md:29-35`).

## Strategy, plan, and session intent versus verified behavior

### Claimed/target intent

* The product strategy says context assembly should be a **bounded compiler** receiving a verified principal and policy and returning assembled context plus a manifest; the manifest should carry directive version, visibility filters, score/provenance, freshness/confidence, category token counts, model/tokenizer identity, cache state, degradation, PII/quarantine decisions, and wrapper version (`IBEX Harness_ Product Strategy, Gap Audit, and Recommended Redesign.md:456-479`).
* The same strategy calls for `ContextEnvelope` as a typed, deterministic policy result with tenant/source/trust/provenance/sensitivity/expiry/content hash and explicit reservation/packing semantics (`...md:967-973`).
* The canonical context contract requires principal/purpose/scope/policy/status verification, exact-key checkpoints/session state, active-authorized hard filtering before rank, authoritative tokenizer packing, safe rendering, and typed envelope output (`web/engineering/architecture-v2/08-context-and-memory-contract.md:9-22`).
* The implementation plan selects “memory lifecycle + context compiler” as a G6 track after G1/G2/evidence/budget/provider foundations and calls for tombstone races, cross-tenant returned-hit rejection, exact final serialization/tokenizer tests, typed envelope compatibility/redaction/degradation tests, security-failure-no-quality-fallback, and provider-not-called assertions. The plan also says existing component tests are not acceptance and that the context Python suite lacked `pytest` in the supplied session environment (`ibex-harness-implementation-plan.md`, context/memory acceptance section and existing-result caveats around lines 150-155).
* The 2026-10-06 session report explicitly says its PR #934 tranche did not attempt to complete context, memory, provider, MCP, control-plane, or recovery and does not claim completion of G0-G8 (`SESSION_REPORT_2026-10-06.md:12,64-87`).

## Residual subgaps

1. **RPC trust binding:** add authenticated internal transport/interceptor or a verified `PrincipalContext`/policy envelope; reject forged/mismatched org, agent, purpose, resource, and policy epoch before any memory call.
2. **Returned-hit integrity:** compare every returned hit’s org/agent/resource scope to the verified request; reject malformed/mismatched results before score/rank/pack. Preserve an observable integrity-denial reason.
3. **Lifecycle authority:** define the Memory service’s active projection/tombstone/quarantine/retention authority and have Context consume a typed lifecycle-approved projection. Test hot cache, vector, FTS, hydration, failover, replay, deletion, expiry, supersession, and legal hold semantics.
4. **Typed contract:** add an additive, versioned `ContextEnvelope` with ordered typed items, source IDs/types, trust/taint/scope, provenance, redaction/PII/quarantine, source version/commit/freshness/retention, directive/policy versions, retrieval profile/cache state, omission/truncation/degradation, and compatibility/golden fixtures.
5. **Tokenizer authority:** replace character/rune estimates with accepted provider/tokenizer source; carry model/deployment/tokenizer revision and count kind; define deny/no-route/explicitly approved safe fallback for unknown/stale metadata; count final escaped/wrapped output.
6. **Failure policy:** distinguish authorization/integrity/tombstone/policy failures from timeouts/quality outages; deny or typed 503 for authority failures; only approved quality failures may use directive-only/verified-hot fallback; assert provider is not called after deny.
7. **Session state:** decide whether checkpoint state is in GAP-05 scope; if yes, add exact-key authoritative read and lineage; if not, freeze/document that `recent_messages` is the only history source.
8. **Evidence/privacy:** persist a redacted manifest/degradation event through the canonical outbox with tenant/run/request/policy joins, stable identity, replay/deletion fences, and no raw prompt/memory bodies in ordinary telemetry.
9. **Acceptance operations:** publish named-profile live 100K/concurrency/cold-warm benchmark artifacts and measured p50/p95/p99; add deletion/read-after-delete and restore/replay certificates; record owner, commit/config/dependency digests, limitations, and review expiry in the status ledger.

## Dependencies and shared-boundary ownership

* **G0 contract freeze / Architecture + Security + Product:** freeze the context envelope, trust labels, policy/directive snapshot binding, tokenizer authority, failure taxonomy, supported profiles, privacy/retention, and whether exact-key session reads are in scope. No new boundary should be treated implementation-ready before G0.
* **G1 Principal/Auth + Proxy:** owns verified caller identity, token-bound agent rule, purpose/resource scope, policy epoch, protected-route verifier readiness, and authenticated proxy→context transport. PR #934 improves this upstream but does not propagate a typed principal to Context.
* **Memory lifecycle (Memory + Context):** Memory owns active projections, status, validity intervals, tombstones/deletion fan-out, quarantine, retention/legal hold, and authoritative read predicates. Context owns consumption/filtering and must not infer lifecycle authority from untyped HTTP fields. PR #936 is partial dependency hardening.
* **Provider/catalog/tokenizer (Provider + Context):** provider/catalog owns immutable model/deployment/tokenizer metadata and freshness; Context owns reservation/packing semantics and must carry identity/count kind in the envelope. Current `capability_catalog.py` plus heuristic `estimate.py` is not that authority.
* **Evidence/Recovery (Evidence/Security + Platform):** owns redacted durable manifest/degradation events, outbox identity/ack/replay, deletion fences, sink dedupe, retention, restore, and RPO/RTO. Proxy currently contributes only metrics/candidate extras.
* **Session/Run (Session + Context):** owns checkpoint/session state and exact-key reads; current Session store exposes no history text read, so Context cannot claim checkpoint compilation.
* **Operations/SRE:** names deployment profiles, dependency assumptions, network trust boundary, runtime readiness, benchmark hardware/concurrency/cache state, and acceptance/review dates. External sidecar/auth, deployment, and static-token scoping are not visible in this repository.

## Exact acceptance checks required before GAP-05 can be promoted

1. **G0 artifact:** dated owner-approved contract packet links the exact commit, context proto/envelope version, authority matrix, trust labels, error/deadline/cancel/retry/replay/privacy/retention/tombstone semantics, supported profile, dependencies, and review expiry.
2. **Authenticated RPC negative matrix:** forged org/agent IDs, wrong-token org, token-agent mismatch, missing/stale principal, wrong purpose/resource, stale policy epoch, non-loopback unauthenticated startup, and malformed internal envelope all deny before memory calls; assert zero provider calls after denial.
3. **Returned-hit integrity:** mock memory returns cross-org, wrong-agent, deleted, expired, superseded, quarantined, malformed, and mismatched lifecycle rows; every case is rejected/quarantined before ranking and produces typed integrity/degradation evidence.
4. **Lifecycle/tombstone race:** concurrent delete/tombstone versus Redis hot cache, vector, FTS, hydration, replay, export, restart, and restore never resurrects or returns data; legal hold blocks purge but not suppression; `valid_until` boundaries are tested on every registered path.
5. **Typed envelope compatibility:** generated proto/runtime golden fixtures cover ordered items, source/type/trust/scope/provenance, redaction/PII/quarantine, source version/freshness/retention, directive/policy versions, retrieval profile/cache state, omissions (`budget`, max-memory truncation, filter, timeout, failure), degradation reason, schema evolution, and privacy-safe evidence.
6. **Authoritative tokenizer:** final serialized output (directive/history/memory wrappers, escaping, Unicode, hostile fields, tools, output/reasoning reserve) is counted by the accepted tokenizer and never exceeds the total budget; unknown/stale tokenizer metadata follows the frozen typed deny/no-route or approved fallback policy.
7. **Failure taxonomy:** backend 401/403/auth/policy/tombstone/integrity failures deny or return typed 503 and make no provider call; ordinary timeout/quality outage follows only the approved directive-only or verified-hot fallback; cancellation/deadline leaves no leaked work.
8. **Session decision/check:** if in scope, exact-key checkpoint/session state is retrieved from its authority and lineage is represented; otherwise a contract test/documentation check proves `recent_messages` is intentionally the sole history input and `session_id` is not a false capability.
9. **Evidence/recovery:** manifest/degradation events are redacted, tenant/run/request/policy joined, idempotently replayable, deletion-fenced, and reconstructable after crash/ack loss/restore; ordinary logs/evidence contain no raw prompt/memory bodies/secrets/unredacted PII.
10. **Profile benchmark:** run and commit stub plus realistic 100K corpus open-loop profiles with workload, hardware, concurrency, warm/cold state, queue/error policy, tokenizer/catalog/config digests, and measured p50/p95/p99. The gate must fail on regression; README’s live harness currently does not fail on p99 miss (`benchmarks/context/README.md:21-35`).
11. **Status promotion:** canonical ledger records source entry point/commit, passing test/benchmark/recovery/hosted artifact links/digests, deployment profile/dependency assumptions, owner/date, limitations, and re-review date. Until then retain `provisional`/`partial`/`specified`, never `shipped-accepted`.

## Risks and uncertainties

* **Critical security risk:** direct non-loopback context gRPC trusts caller-supplied IDs. A UUID parse, proxy-generated string, or static memory token is not caller authentication.
* **Authorization/fallback confusion:** generic HTTP error handling makes 401/403 indistinguishable from a quality outage and can yield L2/directive-only output instead of a security denial.
* **Stale/deleted data risk:** PR #936’s backend fences are good, but context drops lifecycle fields and has no compiler-level read-after-delete or cache/replay proof.
* **Budget availability risk:** heuristic counts can undercount provider-specific tokens and escaped/wrapped content; the existing tests demonstrate only the same estimator’s internal ceiling.
* **Evidence/privacy risk:** a typed manifest must explain decisions without logging raw prompt/memory bodies, secrets, embeddings, or unredacted PII. Current evidence extras are not a complete manifest.
* **Deployment uncertainty:** repository inspection cannot establish whether this gRPC service is deployed, whether a private authenticated sidecar exists, whether the configured static memory token is tenant-scoped, or which profile/SLO is claimed.
* **Test execution uncertainty:** the supplied memo/session evidence says Python context tests could not run in the available environment because `pytest` was unavailable; therefore this audit treats checked-in tests as inspected evidence, not an executed pass. The cited Go context client/proxy test command was reported passing in the memo, but no whole-compiler/profile acceptance is inferred.
* **Architecture authority uncertainty:** architecture-v2/ADR documents are specified/accepted component decisions, but no dated G0 exit/owner acceptance artifact was found. ADR acceptance does not upgrade context assembly to shipped acceptance.

## Bottom line

Keep GAP-05 **open for acceptance and provisional for the implemented local path**. Preserve the current assembler as a useful baseline. Close G0 contract/authority decisions first; then G1 principal/tenant/failure semantics; then the additive typed envelope plus G6 lifecycle/tombstone integration; then evidence/recovery and named-profile benchmarks. PRs #934 and #936 reduce upstream security/lifecycle risk, while #937 is unrelated; none closes the context compiler gap.
