Personal Access Tokens (PATs) are the primary client credential for IBEX Harness. Each token is scoped to an organization, carries a permission bitmap, and is verified by Argon2id hash lookup — only the hash is stored; the plaintext is shown **once** at creation ([ADR-0007](https://github.com/Rick1330/ibex-harness/blob/main/engineering/adr/0007-auth-token-validation.md), [ADR-0010](https://github.com/Rick1330/ibex-harness/blob/main/engineering/adr/0010-cryptography-policy.md)).

::callout
---
{"type":"danger","title":"Secret handling"}
---

  Never log, commit, or paste PATs into tickets. Store in environment variables or a secrets manager. Log only an 8-character prefix in application code — see [Secrets and keys](/docs/security/secrets-and-keys).

::

## PAT wire format

```text
ibex_pat_<token_uuid>_<secret>
```

Example dev token (from `make db-seed`):

```text
ibex_pat_00000000-0000-0000-0000-000000000004_LOCALDEVELOPMENTONLY
```

The auth service parses the prefix, looks up `token_uuid` in `ibex_core.tokens`, and verifies the secret with Argon2id. Revoked tokens fail immediately regardless of hash match.

## Permission bitmap

Tokens encode capabilities as a 64-bit bitmap ([ADR-0009](https://github.com/Rick1330/ibex-harness/blob/main/engineering/adr/0009-permission-bitmap.md)). Common bits for proxy integrators:

| Bit | Name | Needed for |
| --- | --- | --- |
| — | `ProxyChatCompletion` | `POST /v1/chat/completions` |
| — | `TokenCreate` | `CreateToken` gRPC |
| — | `TokenRevoke` | `RevokeToken` gRPC |

`ProxyChatCompletion` is a composite of `MemoryRead | SessionCreate | SessionRead | SecretUse`. The `SecretUse` bit is required because provider credential resolution may fetch a sealed platform or BYO key. It requires step-up for human sessions; a machine PAT must be issued deliberately with that scope.

## Quick start with seed data

::steps

### Migrate and seed

    `make db-migrate && make db-seed` — idempotent; refuses production DSNs.
  
### Export env vars

    Seed output sets `IBEX_DEV_TOKEN`, `IBEX_DEV_AGENT_ID`, `IBEX_DEV_ORG_ID`.
  
### Smoke test

    `make dev-smoke` — validates probes and mock-mode chat (HTTP 200 for registered models) with seeded credentials.
  
::

Fixed seed IDs: org `00000000-0000-0000-0000-000000000001`, agent `00000000-0000-0000-0000-000000000003`.

## Create via gRPC

`CreateToken` requires an existing admin bearer with `TokenCreate` permission.

::tabs

:::tabs-item{label="grpcurl"}

```bash
grpcurl -plaintext \
  -H "authorization: Bearer ibex_pat_<admin-uuid>_<secret>" \
  -d '{"org_id":"<org-uuid>","name":"dev-pat","type":1,"permissions":23}' \
  localhost:9091 ibex.auth.v1.AuthService/CreateToken
```
  
:::

:::tabs-item{label="Validate (no auth)"}

```bash
grpcurl -plaintext \
  -d '{"access_token":"ibex_pat_<uuid>_<secret>"}' \
  localhost:9091 ibex.auth.v1.AuthService/ValidateToken
```
  
:::

::

The response field `plaintext` is the only chance to copy the secret. Persist it immediately.

## CreateToken parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `org_id` | `string (uuid)` | Yes | Organization that owns the token. Must match caller's org. |
| `name` | `string` | Yes | Human-readable label for audit and ListTokens. |
| `type` | `integer` | Yes | Token type enum from proto (1 = standard PAT). |
| `permissions` | `int64` | Yes | Permission bitmap. Use packages/permissions constants in Go. |

## Revoke a token

Immediate invalidation — no grace period:

```bash
grpcurl -plaintext \
  -H "authorization: Bearer ibex_pat_<admin-uuid>_<secret>" \
  -d '{"org_id":"<org-uuid>","token_id":"<token-uuid>"}' \
  localhost:9091 ibex.auth.v1.AuthService/RevokeToken
```

Revoked tokens return `401` on the next proxy request.

## Rotation procedure

::process-steps
---
{"steps":[{"title":"Issue replacement","description":"CreateToken with the same org and desired permissions."},{"title":"Deploy new secret","description":"Update client env vars or secrets manager entry."},{"title":"Verify traffic","description":"Probe /v1/internal/auth-probe with the new PAT."},{"title":"Revoke old token","description":"RevokeToken on the previous token_id — instant cutover."}]}
---
::

Never rotate by deleting rows in Postgres — use the gRPC API so audit and revocation caches stay consistent.

## Operator checklist

::callout
---
{"type":"tip","title":"Production readiness"}
---

  Before promoting a PAT beyond dev: confirm permissions are minimal, expiry policy is documented, and rotation runbook is assigned.

::

- [ ] Permissions follow least privilege (`ProxyChatCompletion` only for LLM clients that need provider credentials)
- [ ] Token name identifies the owning service or agent
- [ ] Plaintext stored in vault, not `.env` committed to git
- [ ] Revocation tested in staging
