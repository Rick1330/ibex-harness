The auth service is the identity plane. It owns organizations, users, agents, PATs, provider credentials, operator sessions, and signed policy snapshots. The proxy calls it over gRPC on every protected request.

::page-status{status="IMPLEMENTED" verified="2026-10-21" note="Local identity plane; hosted operator sessions remain a separate gate"}
::

## Surface

| Surface | Endpoints |
| --- | --- |
| HTTP | `/health`, `/ready`, `/metrics` |
| gRPC | Token, agent, provider-credential, operator-session, and policy-snapshot methods |
| Management REST | Owned by `services/api`, not auth |

There is no public auth REST token API. Use gRPC directly for internal administration or the management API for tenant management.

## gRPC contract

| RPC | Caller auth | Purpose |
| --- | --- | --- |
| `ValidateToken` | None; private network only | Resolve org, subject, permissions, and token identity |
| `ValidateAgent` | None; called after token validation | Confirm the agent belongs to the token org and is active |
| `CreateToken` / `RevokeToken` / `ListTokens` | Bearer with `TokenCreate` / `TokenRevoke` | PAT lifecycle |
| `CreateProviderCredential` / `GetProviderCredential` / `DeleteProviderCredential` / `ListProviderCredentials` | Org permission check | Sealed BYO-provider credentials; metadata only on read |
| Operator session / TOTP methods | Session and step-up rules | Login, refresh, logout, TOTP primitives |
| `IssuePolicySnapshot` | Authenticated principal | Mint an RS256 `policy-snapshot.v1` envelope |

`ValidateToken` has no caller bearer, so it must stay on a trusted private network. `IBEX_AUTH_VALIDATE_RPM` is a per-proxy-host aggregate cap, not client-facing internet rate limiting.

## Permission model

The 64-bit bitmap lives in `packages/permissions/permissions.go`.

| Set | Includes |
| --- | --- |
| `AgentDefault` | Memory read/write, session create/read, trace read |
| `ProxyChatCompletion` | Memory read, session create/read, secret use |
| `ReadOnly` | Memory read, directive read, session read, trace read |
| `Admin` | Agent default plus management bits |

High-risk bits such as `SecretUse`, `OperatorRawRead`, `OperatorExport`, and `PolicyChange` require step-up. `CreateToken` cannot grant permissions the caller does not hold.

## Validation and tenancy

- PATs are stored as Argon2id hashes. The plaintext is returned once.
- `ValidateToken` returns the organization and permission bitmap.
- `ValidateAgent(agent_id, org_id_from_token)` rejects cross-org, unknown, suspended, or archived agents.
- Tenant tables use RLS and explicit `org_id` predicates.
- Revocation propagates through Redis when configured; the proxy auth cache is gated on a healthy revocation channel.
- Policy snapshots bind organization, subject, selected agent, permissions, epoch, and issue/expiry time. Issuance fails closed when no signing key is configured.

## HTTP endpoints

| Endpoint | Purpose |
| --- | --- |
| `GET /health` | Liveness |
| `GET /ready` | PostgreSQL and gRPC readiness |
| `GET /metrics` | Prometheus exposition |

Defaults: HTTP `8081`, gRPC `9091`.

## Failure modes

| Condition | Effect |
| --- | --- |
| PostgreSQL down | `/ready` fails; identity operations fail |
| gRPC listener down | Proxy reports auth unavailable |
| Invalid PAT | `401` at the proxy |
| Agent mismatch | `403 AGENT_NOT_AUTHORIZED` |
| Missing policy signing key | `IssuePolicySnapshot` fails closed outside development |
| Revocation channel unhealthy | Auth cache is not used |

## Run locally

```bash
POSTGRES_DSN=postgres://ibex:ibex@localhost:5432/ibex?sslmode=disable \
IBEX_GRPC_PORT=9091 \
  go run ./services/auth/cmd/auth
```

## Explicitly not in auth

- Public REST token management.
- Browser login UI.
- OAuth authorization-server behavior.
- Hosted multi-zone identity guarantees.
- Operator session integration is not claimed as complete for hosted use.
