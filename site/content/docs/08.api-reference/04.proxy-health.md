Both Go services expose three operational HTTP routes on their respective **`IBEX_PORT`** values: proxy **8080**, auth **8081**. These endpoints are unauthenticated and intended for load balancers, Kubernetes probes, and Prometheus scrapes.

Apply the same three routes on **both** `http://localhost:8080` (proxy) and `http://localhost:8081` (auth).

## Response schemas

### GET /health

Always returns **200** with minimal JSON:

```json
{
  "status": "ok",
  "checks": {}
}
```

Use for **liveness** probes. Failure → restart the pod/process.

### GET /ready

Returns dependency detail:

```json
{
  "status": "ok",
  "checks": {
    "postgres": { "status": "ok", "latency_ms": 2 },
    "auth_grpc": { "status": "ok", "latency_ms": 4 }
  }
}
```

| Top-level `status` | HTTP | Meaning |
| --- | --- | --- |
| `ok` | 200 | All critical checks passed |
| `degraded` | 200 | Critical OK; advisory failure |
| `unhealthy` | 503 | At least one critical check failed |

Per-check timeout: **500ms**. Overall request budget: **750ms**.

### Critical checks by service

| Service | Check name | What it verifies | On failure |
| --- | --- | --- | --- |
| Auth | `postgres` | `SELECT 1` via pool | 503 `unhealthy` |
| Auth | `grpc` | TCP reachability to gRPC listen address | 503 `unhealthy` |
| Proxy | `auth_grpc` | ValidateToken with sentinel probe token; `Unauthenticated` = reachable | 503 `unhealthy` |
| Proxy | `redis` | `PING` over RESP | 503 `unhealthy` |
| Proxy | `postgres` | `SELECT 1` when a pool exists | 503 `unhealthy` |

Proxy treats `postgres` as **critical**, not advisory: directive, session and idempotency storage need it, so a failed `SELECT 1` fails readiness rather than reporting `degraded` (`services/proxy/internal/bootstrap/wire.go`:501-506). Only `selfhosted_llm` and `tokenizer` are advisory; an advisory failure keeps HTTP 200 with `status: degraded`.

Memory and API readiness use a different envelope. Memory `/ready` returns 503
`{"error":{"code":"service_not_ready",...,"dependency":"auth|postgres|redis|bootstrap|timeout|memory"}}`
for the failed live dependency (`services/memory/app/probes.py`:38-75). API
`/ready` returns 503 with `code: service_degraded` for `auth gRPC not reachable`,
`database not reachable`, `redis not reachable`, a timed-out budget, or a draining
process (`services/api/app/probes.py`:34-90).

Use **readiness** probes for load-balancer membership. A failing `/ready` removes traffic without restarting the pod.

## Probe examples

::tabs

:::tabs-item{label="curl"}

```bash
# Liveness
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/health

# Readiness (proxy — needs auth gRPC + Redis)
curl -s http://localhost:8080/ready | jq

# Metrics scrape
curl -s http://localhost:8080/metrics | head
```
  
:::

:::tabs-item{label="Kubernetes (preview)"}

```yaml
livenessProbe:
  httpGet:
    path: /health
    port: 8080
  periodSeconds: 10
readinessProbe:
  httpGet:
    path: /ready
    port: 8080
  periodSeconds: 5
  failureThreshold: 3
```
  
:::

## Metrics catalog

Scrape `/metrics` on both services. Key series include:

| Metric | Type | Labels | Service |
| --- | --- | --- | --- |
| `ibex_proxy_requests_total` | Counter | route, method, code | Proxy |
| `ibex_proxy_auth_validate_duration_seconds` | Histogram | result | Proxy |
| `ibex_auth_validate_token_duration_seconds` | Histogram | result | Auth |
| `ibex_auth_validate_agent_duration_seconds` | Histogram | result | Auth |

Full catalog: [ADR-0021](https://github.com/Rick1330/ibex-harness/blob/main/engineering/adr/0021-prometheus-metric-catalog.md).
