The proxy exposes an OpenAI-shaped chat endpoint for SDK drop-in compatibility. After auth, agent verification, rate limits, and request normalization, the proxy forwards to the configured LLM provider (mock or live).

::endpoint

Decision records: [ADR-0012](https://github.com/Rick1330/ibex-harness/blob/main/engineering/adr/0012-proxy-request-normalization.md) (normalization), [ADR-0035](https://github.com/Rick1330/ibex-harness/blob/main/engineering/adr/0035-chat-idempotency-key.md) (Idempotency-Key). Path `org_id` on org-scoped probes must match the token org.

## Required headers

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `Authorization` | `string` | Yes | Bearer PAT issued by auth service. |
| `X-IBEX-Agent-ID` | `string (uuid)` | Yes | Calling agent; must belong to the token organization. |
| `Content-Type` | `string` | Yes | Must be application/json (charset suffix allowed). |

## Optional headers

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `Idempotency-Key` | `string` | No | Opaque client key (max 256 chars). Within TTL (default 24h), the same key + same request fingerprint replays the first completion without a second upstream call. Redis key: idempotency:{org_id}:{key} (org from token). See ADR-0035. |
| `X-IBEX-Session-ID` | `string` | No | Sticky session external id (max 64 chars). Missing/invalid values are minted and echoed on the response. Durable sessions require POSTGRES_DSN — see Sessions. |

### Idempotency behavior

- **Missing header:** unchanged — every request calls the provider.
- **Hit (same key + fingerprint):** replay stored HTTP status and body; no provider call; no second session checkpoint / trace.
- **Conflict (same key, different body):** `409` with `IDEMPOTENCY_KEY_REUSE`.
- **In progress:** `409` with `IDEMPOTENCY_IN_PROGRESS` — retry after a short backoff.
- **Transient upstream errors (429 / 5xx):** pending claim is released so the same key can retry.
- **Streaming:** `stream=true` is supported and proxies SSE. Combining it with `Idempotency-Key` returns `400 VALIDATION_ERROR` because replay covers non-streaming responses only.
- **Redis down / timeout:** fail-open — request proceeds without dedupe (billing risk under Redis outage).
- The key is **not** forwarded to OpenAI.

## Request body (parsed fields)

Per ADR-0012, the proxy decodes OpenAI-shaped JSON and ignores unknown top-level keys:

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `model` | `string` | Yes | Model identifier (validated in ADR-0013; max 256 chars). |
| `messages` | `array` | Yes | Objects with role and content strings; max 1000 messages. |
| `stream` | `boolean` | No | Enables SSE streaming. `Idempotency-Key` requires `stream=false`. Other common OpenAI fields are parsed or ignored per ADR-0012. |

After successful parse, the proxy logs **metadata only** (`org_id`, `request_id`, `model`, `message_count`, `stream`) — never message content.

## Response

Successful non-streaming completions return provider-shaped JSON. Streaming requests receive an SSE response. Response headers include `X-Request-ID`, `X-Trace-ID`, and `X-Response-Time` per [ADR-0013](https://github.com/Rick1330/ibex-harness/blob/main/engineering/adr/0013-proxy-input-validation-and-error-envelope.md). Session sticky header `X-IBEX-Session-ID` may be set when session lifecycle is enabled.

Mapped provider failures use the stable error envelope (`PROVIDER_TIMEOUT`, `RATE_LIMITED`, etc.).

## Try it locally

::tabs

:::tabs-item{label="curl"}

```bash
IDEM_KEY="$(uuidgen)"
BODY='{"model":"gpt-4o","messages":[{"role":"user","content":"hello"}]}'
curl -s -w "\nHTTP %{http_code}\n" \
  -X POST http://localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer ${IBEX_DEV_TOKEN}" \
  -H "X-IBEX-Agent-ID: ${IBEX_DEV_AGENT_ID}" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: ${IDEM_KEY}" \
  -d "${BODY}"
# Retry with the same key + body to verify replay (no second upstream completion):
curl -s -w "\nHTTP %{http_code}\n" \
  -X POST http://localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer ${IBEX_DEV_TOKEN}" \
  -H "X-IBEX-Agent-ID: ${IBEX_DEV_AGENT_ID}" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: ${IDEM_KEY}" \
  -d "${BODY}"
```
  
:::

:::tabs-item{label="python"}

```python
import os, uuid, requests

idem_key = str(uuid.uuid4())
payload = {"model": "gpt-4o", "messages": [{"role": "user", "content": "hello"}]}
headers = {
    "Authorization": f"Bearer {os.environ['IBEX_DEV_TOKEN']}",
    "X-IBEX-Agent-ID": os.environ["IBEX_DEV_AGENT_ID"],
    "Content-Type": "application/json",
    "Idempotency-Key": idem_key,
}
r1 = requests.post("http://localhost:8080/v1/chat/completions", headers=headers, json=payload)
r2 = requests.post("http://localhost:8080/v1/chat/completions", headers=headers, json=payload)
print(r1.status_code, r2.status_code, r1.headers.get("X-Request-ID"))
```
  
:::

With `IBEX_LLM_MODE=mock`, expect HTTP **200** and an OpenAI-shaped JSON body. The second request reuses the same `Idempotency-Key` and body so replay can be verified without a second upstream completion.
