Every durable customer entity is scoped to an organization. PostgreSQL is the source of truth for identity, memory, sessions, directives, billing configuration, privacy, and evidence metadata. pgvector stores embeddings in the same database. Redis is ephemeral. ClickHouse is a projection.

::page-status{status="PROVISIONAL" verified="2026-10-21" note="Schema is implemented locally; typed lifecycle and hosted isolation proof remain open"}
::

## Stores

| Store | Role | Authoritative? |
| --- | --- | --- |
| PostgreSQL `ibex_core` | Identity, sessions, directives, memories, evidence, privacy | Yes |
| PostgreSQL `ibex_billing` | Rate cards, budget periods, enforcement decisions | Yes |
| pgvector | Memory embeddings and HNSW index | Yes, inside PostgreSQL |
| Redis | Rate limits, auth cache, hot memory, revocation | No |
| ClickHouse `ibex` | Traces, usage facts, projections | No |
| MinIO / S3 | Archives and deletion artifacts | Not certified |

There is no `projects` table. Do not design around project-scoped URLs.

## Tenant invariants

1. **`org_id` comes from a verified principal.** It is never accepted from a chat body.
2. **Application predicates are mandatory.** Every query filters `org_id`, even when RLS is enabled.
3. **RLS is a backstop.** Transactions set `SET LOCAL app.current_org_id`; a missing value must fail closed.
4. **Resource lookups use not-found semantics where enumeration matters.** Proxy identity mismatches are 403; management and memory lookups are 404 for unknown or out-of-tenant IDs.
5. **Redis keys are tenant-prefixed.** Global keys are limited to explicitly safe metadata such as revocation broadcast.
6. **ClickHouse has no RLS.** Every query must carry its own `org_id` predicate; there is no global enforcement switch.
7. **Cross-tenant tests are required.** A feature is not done until Org A cannot read Org B through the new path.

## Memory cardinality

- A memory belongs to one organization and one agent.
- A memory may have multiple labels, but only one primary category projection.
- Supersession edges are directional and tenant-bound.
- Active search excludes `status != 'active'` and deleted rows.
- Historical conflict search is an internal capability, not an ordinary user read mode.

## Migrations

PostgreSQL migrations currently run through `000047_relay_fence_checker`. ClickHouse migrations include `llm_traces`, `usage_facts`, and `evidence_events`. Apply them with the repository migration targets; do not hand-edit a live schema.

## What is not proven

- Complete tenant isolation across backups, archives, caches, and projections.
- Typed memory provenance and a durable revision ledger.
- Deletion timing for every derived copy.
- Hosted/HA recovery and measured RPO/RTO.

See [Tenant isolation](/docs/security/tenant-isolation) and [Status and evidence](/docs/architecture/status-and-evidence).
