IBEX Harness uses Go for the latency-critical request path and Python for memory, context, extraction, and operator services. This page describes responsibilities; see [Status and evidence](/docs/architecture/status-and-evidence) for the claim boundary.

## Request path services

### LLM Proxy

:status-badge{status="IMPLEMENTED"}

**Go · HTTP 8080**

The public edge for LLM traffic. Protected routes run a fixed middleware chain: body limit → content type → auth → agent verification → policy snapshot → rate limit → budget → directive/session → parse → provider routing → handler. Context assembly runs inside the handler before the provider call.

| Responsibility | Status |
| --- | --- |
| PAT validation through auth gRPC | Implemented |
| Agent binding (`X-IBEX-Agent-ID`) | Implemented |
| Per-org rate limits | Implemented |
| OpenAI-compatible normalization | Implemented |
| Mock and live provider forwarding | Implemented |
| Directives, sessions, idempotency | Implemented |
| Context assembly client and fallback | Provisional |
| Async ClickHouse traces | Implemented when configured |

### Auth Service

:status-badge{status="IMPLEMENTED"}

**Go · HTTP 8081 · gRPC 9091**

Identity authority. Issues and revokes PATs, validates tokens and agents, carries permissions, publishes revocations, and issues signed policy snapshots.

| RPC | Purpose |
| --- | --- |
| `ValidateToken` | Resolve org, permissions, and token identity. |
| `ValidateAgent` | Confirm agent membership and binding. |
| `CreateToken` / `RevokeToken` / `ListTokens` | PAT lifecycle. |

See [Auth overview](/docs/auth/overview) and [ADR-0011](https://github.com/Rick1330/ibex-harness/blob/main/engineering/adr/0011-proxy-auth-client.md).

## Memory and context services

### Memory Service

:status-badge{status="IMPLEMENTED"}

**Python/FastAPI**

Tenant- and agent-scoped memory storage, embedding orchestration, dedup, conflict candidates, validity-fenced reads, hot cache, feedback, and forget. Locally evidenced; typed lifecycle and deletion certification remain open. See [Memory overview](/docs/memory/overview).

### Context Assembly

:status-badge{status="PROVISIONAL"}

**Python/gRPC**

Budget calculation, parallel retrieval, composite ranking, relevance gating, packing, and formatting. Caller authentication and the deadline boundary remain open. See [Context assembly](/docs/context/overview).

### Embedding Service

:status-badge{status="IMPLEMENTED"}

**Python/FastAPI**

Converts text to vectors for memory writes and search. The CPU stub, TEI, and hosted profiles are implemented; readiness depends on the selected backend. Embedding dimensions must not be mixed within an index.

### Extraction Workers

:status-badge{status="PROVISIONAL"}

**Python/Celery**

Extract memories from completed turns, write them to memory, orchestrate organization deletion, reconcile billing usage, and persist dead letters. The scheduled maintenance sweep is a no-op. Queue durability and exactly-once projection effects are not certified.

## Operator and integration surfaces

### MCP Memory

:status-badge{status="PROVISIONAL"}

Search, write, and feedback tools over MCP. Audit is logging-first, not evidence-grade.

### MCP Operator Gateway

:status-badge{status="IMPLEMENTED"}

Read-only metadata tools (`session.get`, `run.get`, `evidence.query`, `budget.get`), default-off. Authorization uses the permission bitmap; PolicySnapshot resource evaluation remains deferred. Not operator readiness.

### Management API and Console

:status-badge{status="PROVISIONAL"}

Mounted management routes and an operator Console exist. They are not production operator readiness, and hosted runtime topology is incomplete.
