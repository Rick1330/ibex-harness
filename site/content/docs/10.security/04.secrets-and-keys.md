Secrets — database passwords, JWT signing keys, LLM provider API keys, and Redis credentials — must never appear in git, logs, or client bundles. This page lists the secret variables used by the current services and the rotation expectations that apply in production.

::callout
---
{"type":"danger","title":"Never commit secrets"}
---

  Export secrets into host process environments locally. For containers, pass an explicit Compose `--env-file` (the
  root dev Make targets do this for `infra/compose/dev/.env.example`). `--env-file` supplies interpolation values; it
  does not by itself pass every entry into a container, so a container value must also appear under the service's
  `environment`. Compose uses a project `.env` for interpolation when `--env-file` is absent, and an exported shell
  variable overrides the file. Copying an `.env.example` file does not make the Go or Python services load it; Nuxt does
  load `services/console/.env` during `nuxt dev` and `nuxt build`. The dev Compose worker takes its database address from
  `IBEX_WORKER_DATABASE_URL` when set, and that address must be reachable from inside the container (for example
  `postgres:5432`, not `localhost:5432`). Use a secrets manager (Vault, cloud Secrets Manager, Kubernetes External
  Secrets) in staging and production. CI runs gitleaks on every pull request.

::

## Allowed secret locations

| Environment | Storage |
| --- | --- |
| Local development | Exported process environment for host services; explicit Compose `--env-file` for container values. Do not rely on copied `.env` files. |
| Staging / production | Vault, cloud secrets manager, or K8s External Secrets |
| **Forbidden everywhere** | Git commits, Helm values in repo, docs, test fixtures, stdout logs |

Browser bundle rule: no secret belongs in public browser configuration. The Console exposes only `NUXT_PUBLIC_IBEX_ENV` (an environment label); credentials and upstream settings stay in the server-only BFF.

## Secret variables

### Database

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `POSTGRES_DSN` | `connection string` | Yes | Full Postgres DSN for auth service (postgres://...). |
| `IBEX_API_DATABASE_URL` | `connection string` | Conditional | Async PostgreSQL DSN for the Management API (`postgresql+asyncpg://...`). |
| `POSTGRES_MIGRATE_DSN` | `connection string` | No | Go migrate runner DSN; derived from POSTGRES_DSN when unset. |
| `POSTGRES_PASSWORD` | `string` | No | Used only when building DSN from host/port/user parts. |

### Redis (proxy)

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `REDIS_URL` | `url` | No | e.g. redis://:password@host:6379/0. Empty disables rate limiting (Noop limiter). |

### LLM providers (proxy, live mode)

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `OPENAI_API_KEY` | `string` | Yes | Required when IBEX_LLM_MODE=live and using OpenAI. |
| `ANTHROPIC_API_KEY` | `string` | Yes | Required when IBEX_LLM_MODE=live and using Anthropic. |
| `IBEX_LLM_MODE` | `enum` | No | Set mock for local dev without provider keys. |

### JWT signing (auth operator sessions)

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `JWT_PRIVATE_KEY_PEM` | `PEM` | Conditional | RS256 signing key for operator sessions. Omit only for a single-instance auth deployment that does not issue sessions. Never expose to proxy or clients. |
| `JWT_ISSUER` | `string` | No | Issuer claim; default `ibex-harness`. |
| `JWT_AUDIENCE` | `string` | No | Audience claim; default `ibex-dashboard`. |
| `JWT_ACCESS_TOKEN_TTL` | `duration` | No | Access lifetime; default 15m. |
| `JWT_REFRESH_TOKEN_TTL` | `duration` | No | Refresh lifetime; default 168h. |
| `JWT_STEP_UP_TOKEN_TTL` | `duration` | No | Step-up lifetime; default 5m. |

There is no OIDC client secret or multi-key verification env in the shipped auth configuration. Do not document a key-rotation flow that the service does not implement.

### Token hashing (auth)

Argon2id parameters are configured via `IBEX_ARGON2_MEMORY_KIB`, `IBEX_ARGON2_TIME`, and `IBEX_ARGON2_PARALLELISM` per [ADR-0010](https://github.com/Rick1330/ibex-harness/blob/main/engineering/adr/0010-cryptography-policy.md). PAT wire values are hashed before storage; plaintext is returned once at creation and never logged.

## Rotation policy

::steps

### JWT signing keys

    Rotate on a planned schedule with coordinated auth restart. The shipped configuration has one active signing PEM; there is no documented multi-key grace-period keyset. Plan for operator session re-authentication.
  
### Provider credentials

    Prefer org-scoped provider credentials sealed by auth over shared process environment keys. Rotate at the provider, then update the sealed credential through the auth API.
  
### Database credentials

    Rotate every 30 days when using dynamic secrets; update DSN in secrets manager before revoking old creds.
  
### LLM provider keys

    Customer-managed for BYOK; update via API without downtime when orgs rotate keys.
  
::

## Cryptographic standards

| Use case | Algorithm |
| --- | --- |
| Password and PAT hashing | Argon2id |
| Dashboard JWT | RS256 |
| Symmetric encryption | AES-256-GCM |
| Content hashing | SHA-256 |

Forbidden: MD5, SHA-1, custom crypto, home-grown JWT verification, storing encryption keys next to ciphertext.

## Logging and observability

::callout
---
{"type":"warning","title":"Safe logging"}
---

  Log token prefixes (first 8 characters) at most. Never log raw bearer tokens, password hashes, DSN passwords, or full provider API keys.

::

Structured JSON logs include `request_id` and `trace_id` when OTel is initialized. `IBEX_LOG_LEVEL=DEBUG` may expose sensitive details — disable broadly in production.

## Startup validation

Services fail fast at startup when required secrets are missing or when production detects unsafe dev defaults (e.g. `IBEX_ENV=production` with mock auth). Prefer a crash at boot over running with invalid configuration.
