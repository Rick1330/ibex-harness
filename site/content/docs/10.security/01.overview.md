IBEX Harness sits on a high-value data path — LLM traffic, persistent memory, org-scoped tokens, and billing events. Security is an invariant, not a phase. This page summarizes what must always be true and what we defend against on the shipped auth + proxy path.

::callout
---
{"type":"note","title":"Shipped surface"}
---

  Auth, agent identity, rate limits, error envelopes, and **mock-provider** forwarding are exercised by the `security-integration` CI job. Live OpenAI/OpenRouter forwarding is covered by operator smokes (`make dev-smoke-live`), not that job. Memory formatting defenses and the context deadline path are implemented locally. Console MFA and hosted operator hardening remain provisional.

::

## Security objectives

These six objectives (S1–S6) are non-negotiable across every release.

::process-steps
---
{"steps":[{"title":"S1 — Tenant isolation","description":"Org A must never access Org B data via API, database, cache, logs, analytics, or exports. Proxy identity mismatches return 403; resource lookups return 404 where existence leakage is a risk."},{"title":"S2 — Confidentiality of secrets","description":"Tokens, API keys, passwords, and signing keys must never appear in git history, logs, crash dumps, analytics payloads, or client-side bundles."},{"title":"S3 — Integrity of billing and audit records","description":"Billing events and audit logs are append-only, tamper-resistant, and recorded at least once — never silently dropped."},{"title":"S4 — Least privilege authorization","description":"Authentication is not authorization. Every operation checks token validity, permission bitmap, org ownership, and explicit roles for sensitive actions."},{"title":"S5 — Safe prompt and memory handling","description":"Memory content is untrusted input. Write-time quarantine, retrieval-time delimiters, and directive rules reduce prompt-injection risk from stored content."},{"title":"S6 — Secure failure modes","description":"Auth and tenant isolation fail closed. Memory and context injection fail gracefully (degraded quality, still safe). Missing checks never accidentally allow operations."}]}
---
::

## Threat model summary

```mermaid
graph TB
    subgraph external [External threats]
        E1[Stolen API tokens]
        E2[Credential stuffing]
        E3[API abuse / DoS]
        E4[Supply-chain compromise]
    end
    subgraph internal [Internal threats]
        I1[Over-broad machine tokens]
        I2[Developer isolation bypass]
        I3[Logging PII or secrets]
    end
    subgraph ai [AI-specific threats]
        A1[Prompt injection in memory]
        A2[Instruction smuggling via integrations]
        A3[Data poisoning over time]
    end
    external --> Proxy[Proxy + Auth boundary]
    internal --> Proxy
    ai --> Memory[Memory / Context path]
    Proxy --> Auth[Auth gRPC]
    Proxy --> Redis[Redis rate limit]
    Auth --> PG[(Postgres + RLS)]
```

| Category | Examples | Primary controls |
| --- | --- | --- |
| External | Token theft, brute force, cost amplification | PAT hashing (Argon2id), org RPM limits, input size caps |
| Internal | Over-broad machine tokens, missing org filters | RLS + application-layer org checks, bounded permission bitmap |
| AI-specific | Injection stored in memory, role confusion | PII/redaction and quarantine on the write path; delimited retrieval as data. Full prompt-injection proof remains open. |

::callout
---
{"type":"warning","title":"ClickHouse has no RLS"}
---

  Analytics queries must include an explicit `org_id` filter. Some packages reject an empty org or require an org predicate, but there is **no** application-wide enforcement switch. Every hand-written query must carry its own tenant predicate.

::

## Fail closed vs fail open

| Scenario | Behavior |
| --- | --- |
| org_id context not set | **Fail closed** — deny access |
| Token validation incomplete (no safe cache) | **Fail closed** — 503 `AUTH_UNAVAILABLE` |
| Permission check ambiguous | **Fail closed** — 403 |
| Proxy Redis unavailable (rate limit) | **Fail closed** — return 503 `SERVICE_DEGRADED`; do not reach provider work ([ADR-0081](https://github.com/Rick1330/ibex-harness/blob/main/engineering/adr/0081-fail-closed-proxy-runtime-controls.md)) |
| Memory retrieval timeout | **Fail open** — directive-only context |

::callout
---
{"type":"danger","title":"Never disable controls to recover"}
---

  Do not temporarily disable auth, rate limits, or RLS during incidents. Prefer rollback, scale-up, or circuit breakers.

::

## Validated invariants

The following behaviors are enforced by automated security tests in CI:

| Invariant | Expected behavior |
| --- | --- |
| Missing or invalid token | Rejected before handler (401) |
| Cross-org agent header | 403, not 404 |
| Revoked token | Rejected promptly |
| Auth service down | 503 with stable JSON envelope |
| Rate limits | Per-org RPM with correct headers |
| Permission bitmap | Enforced on protected routes |
