## Reading rules

- A proposed ADR has no runtime claim.
- An accepted ADR is a decision, not acceptance evidence.
- A superseded ADR remains useful history; follow the superseding record.
- An ADR can be correct while the implementation is incomplete.
- When an ADR and the status ledger disagree about what is running, the ledger wins.

## Adding a decision

A new ADR is required when a change alters a cross-service contract, trust boundary, data lifecycle, security control, provider boundary, or deployment profile. Pair it with ledger evidence and a review/expiry date.
