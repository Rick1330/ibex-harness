There is an umbrella Helm chart for proxy, auth, API, worker, memory, embedder, and MCP memory. It is **render/lint scaffolding**, not a deployable release.

::page-status{status="PROVISIONAL" verified="2026-10-21" note="Chart renders; checked-in defaults are not deployable"}
::

## What exists

| Artifact | Today | Boundary |
| --- | --- | --- |
| `infra/helm/ibex-harness` | Umbrella chart | Templates for application workloads |
| `values.yaml` | Drill defaults | Sentinel digests; not for a real release |
| `values-staging.yaml` / `values-prod.yaml` | Overlays | Still require real digests and external Secrets |
| Data-plane templates | None | No PostgreSQL, Redis, ClickHouse, or MinIO |
| Migration job | Disabled by default | Must be supplied and executed deliberately |
| Deployment workflow | None | No automated Helm release |

## Render and lint

```bash
helm lint infra/helm/ibex-harness
helm template ibex infra/helm/ibex-harness \
  -f infra/helm/ibex-harness/values.yaml > /tmp/ibex-render.yaml
```

A successful render proves the templates are syntactically valid. It proves nothing about runtime availability, security, or data-plane readiness.

## What blocks a real release

1. Replace sentinel image digests with real artifact digests.
2. Create the external `ibex-redis` Secret (and all other required Secrets) out of band.
3. Provision PostgreSQL, Redis, ClickHouse, and object storage.
4. Run migrations with a preflight and rollback plan.
5. Set the deployment profile so the proxy environment cannot be downgraded.
6. Run `.github/scripts/check-helm-deployable.sh <overlay>`.
7. Establish a deployment workflow and release approval.

::callout
---
{"type":"danger","title":"Do not bypass preflight"}
---

  A direct `helm upgrade` that bypasses release preflight is not approved. The repository has no automated Helm deployment workflow, so an overlay is not release evidence.

::

## Probes

Wire probes to the shipped contracts:

| Probe | Path | Behavior |
| --- | --- | --- |
| Liveness | `/health` | Process responds; no external dependency check |
| Readiness | `/ready` | Critical dependencies only |
| Metrics | `/metrics` | Prometheus scrape |

Auth readiness checks PostgreSQL and its gRPC listener. Proxy readiness checks auth gRPC and Redis. Per-check timeout is 500 ms; overall readiness is bounded at 750 ms.

## Security requirements

- NetworkPolicy restricts gRPC to trusted workloads.
- Service-to-service authentication is configured; plaintext is local-only.
- Secrets come from a managed secret store.
- `org_id` comes from a verified token, never from ingress rewriting alone.
- Cross-tenant resources do not leak existence.
- Pod disruption budgets and shutdown budgets match the service behavior.
- Rollback is by digest, not by mutable tag.

## Observability

The separate `infra/helm/observability` chart is also packaging scaffolding. It does not bundle Alertmanager, the Compose dashboards/rules, or the Loki pipeline. Compose remains the source of truth for local dashboards.
