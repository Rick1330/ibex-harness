The platform ships W3C distributed tracing, bounded Prometheus metrics, and structured JSON logs correlated by `request_id` and `trace_id`. Go services (auth, proxy) have the most complete OTel wiring; Python services expose Prometheus endpoints, and worker and MCP operator also export OTel spans. Treat cross-language trace continuity as partially wired rather than universal.

::callout
---
{"type":"note","title":"Tracing stack"}
---

  Services with HTTP probes expose `/metrics`; the worker exposes a dedicated metrics port. OTel exports to OTLP when `OTEL_EXPORTER_OTLP_ENDPOINT` is set; otherwise spans are no-op or in-process only ([ADR-0019](https://github.com/Rick1330/ibex-harness/blob/main/engineering/adr/0019-opentelemetry-provider-configuration.md)).

::

## Correlation identifiers

Every inbound HTTP request carries:

| ID | Source | Propagation |
| --- | --- | --- |
| `request_id` | `packages/reqid` — UUID v7 | `X-Request-ID` header; all log lines in request scope |
| `trace_id` | OpenTelemetry span context | W3C `traceparent`; `X-Trace-ID` response header |
| `org_id` | Verified token (when authenticated) | Logs and gRPC metadata — never as a metric label |

::callout
---
{"type":"warning","title":"Cardinality budget"}
---

  Prometheus labels must stay bounded. Never label metrics with `org_id`, `agent_id`, or raw URL paths. Per-tenant analytics belong in ClickHouse ([ADR-0021](https://github.com/Rick1330/ibex-harness/blob/main/engineering/adr/0021-prometheus-metric-catalog.md)).

::

## OpenTelemetry

Auth and proxy initialize OTel via `packages/telemetry` at startup:

```mermaid
graph LR
    A[HTTP request] --> B[SpanMiddleware]
    B --> C[Handler / gRPC client]
    C --> D[OTel context propagation]
    D --> E[Logger trace_id field]
```

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | `host:port` | No | OTLP gRPC collector (e.g. localhost:4317). Empty = noop exporter. |
| `OTEL_SAMPLE_RATIO` | `float` | No | Root span sampling ratio via ParentBased + TraceIDRatio. |
| `OTEL_SERVICE_NAME` | `string` | No | Falls back to IBEX_SERVICE_NAME when unset. |
| `OTEL_DEPLOYMENT_ENVIRONMENT` | `string` | No | Falls back to IBEX_ENV (development, staging, production). |

HTTP spans are named `{method} {route_template}` (e.g. `POST /v1/chat/completions`) — never raw paths with UUIDs. Proxy gRPC auth calls propagate trace context via `otelgrpc` client interceptors.

Tail-based 100% export for 5xx traces requires a collector-side sampler. In-process sampling marks span status ERROR on HTTP status ≥ 500 for sampled spans; it cannot retroactively retain an unsampled trace.

## Prometheus metrics

Scrape `GET /metrics` on each service. All metrics register in `packages/metrics` — services never call `prometheus.MustRegister` directly.

### Catalog (selected)

| Metric | Type | Service |
| --- | --- | --- |
| `ibex_proxy_request_duration_seconds` | Histogram | proxy |
| `ibex_proxy_requests_total` | Counter | proxy |
| `ibex_proxy_rate_limited_total` | Counter | proxy |
| `ibex_auth_validate_token_duration_seconds` | Histogram | auth |
| `ibex_auth_grpc_requests_total` | Counter | auth |
| `ibex_db_query_duration_seconds` | Histogram | auth |
| `ibex_process_up` | Gauge | both |

Histogram buckets target the &lt;20ms proxy overhead budget: `0.001 … 5.000` seconds.

## Structured logging

Logs use `packages/logger` — JSON to stdout in production. Every line in a request scope includes `request_id`; when a span is active, `trace_id` is injected automatically.

| Level | When to use |
| --- | --- |
| DEBUG | Local debugging only; never per-request in production |
| INFO | Lifecycle events: startup, config loaded, migration applied |
| WARN | Recoverable anomalies: degraded dependency path, retry succeeded |
| ERROR | Requires action: DB failure, auth service unreachable |

::callout
---
{"type":"danger","title":"Privacy by default"}
---

  Do not log raw tokens, passwords, memory content, or full prompts/responses. Metrics capture per-request volume; logs capture anomalies.

::

### Log level configuration

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `IBEX_LOG_LEVEL` | `enum` | No | DEBUG \| INFO \| WARN \| ERROR |
| `IBEX_LOG_FORMAT` | `string` | No | json in production |

## Middleware order (proxy)

Outer → inner: `RequestContext → Span → metrics → ResponseHeaders → logging → mux`. Auth middleware runs inside the mux after span creation so route templates and trace context are available to metrics and logs.

## Local verification

::steps

### Confirm metrics endpoints

    `curl -s http://localhost:8080/metrics` and `:8081/metrics` return Prometheus text.
  
### Send a traced request

    Include `X-Request-ID` on a proxy call; search service stdout for that ID.
  
### Optional collector

    Point `OTEL_EXPORTER_OTLP_ENDPOINT` at Jaeger or Tempo to visualize spans locally.
  
::
